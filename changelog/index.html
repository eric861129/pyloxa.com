0.1.11

Released 2026-11-17

This update lets you save your own workflows, describe a workflow in one sentence and try Pyloxa on a sample project before you use your own. It adds a verification card to every finished plan, a settings backup you can take to another computer, and a Help menu.

New

  • Try it on a sample project first. The setup wizard offers Start the test drive on its last step and, once an agent is signed in, already on its first steps; the welcome page before you have any project offers it too. If you start from an early step, the wizard closes with default settings and the getting-started checklist lists what's left. Pyloxa creates a small sample repository with a hidden rounding bug and a ready-made plan; nothing runs until you approve it. With two different CLIs, one fixes the bug and the other tests the fix (automatic in Pro; in the free version you choose Have another agent test it). With one CLI, Pyloxa runs the spec's tests itself. Agents can only change files in src/, so a passing result means the bug is really fixed. Before you start, Pyloxa shows who does what and an estimate of the agent turns, tokens and time it will take. The test drive needs git and Node.js, and it uses your own subscriptions or API keys like any other task.
  • A verification card for every finished plan. Below a finished plan, Verification card shows what was checked: who did each task, whether it was cross-tested, the commands Pyloxa ran itself and their results. You can copy it as Markdown. The same card now replaces the verification record in pull request descriptions. An optional last line says “Verified with Pyloxa” only when every result passed the commands Pyloxa ran and every gate passed.
  • My workflows (Pro). On the Workflow page, Save as my workflow keeps your current dispatch mode, brain review, cross-testing, worktree setting, phases and division of work under a name, up to 20. Each project can use a different workflow, and your own rules for a project still come first. Each workflow keeps its last 10 versions: compare any two, or restore one. Without Pro, projects use the global settings and your workflows are kept.
  • Describe a workflow in one sentence (Pro). Choose Describe it on the Workflow page and write what you want, for example “write a spec first and wait for my approval; backend goes to Codex; the brain reviews everything”. The brain drafts a workflow and lists what it couldn't do. You see exactly which settings would change before you apply it to the global settings or save it as one of your workflows.
  • Take your settings to another computer. Settings → Backup and transfer exports your profiles, global rules, brain and dispatch preferences, prompt templates, global shared memory, skills library, appearance and your workflows to one file, and imports it on another computer with a preview of every change. API keys, sign-ins and paths on this computer are never exported. Before an import, Pyloxa backs up this computer's settings, and Restore a backup brings back any of the last five. Export and import are free; Pro settings in the file are kept and pause without Pro.
  • Dispatch packs carry workflows (Pro). A dispatch pack can now include your workflows, and importing one can set the project to use it. What older packs called “workflow and conventions” is now Conventions. Packs made by 0.1.10 still import.
  • Phase progress on plan cards. After you approve a plan with more than one phase, a bar above the plan shows each phase's status and where the plan is. Click a phase to jump to it.
  • Help. The Help menu and the Pyloxa menu in the title bar open Pyloxa Help at pyloxa.com/help/, in English or Traditional Chinese.

Changes

  • The setup wizard starts with how Pyloxa differs from running several agent sessions yourself: it splits work across vendors, runs your tests itself, hands work over when quota runs out and never touches your working folder. It also points out that small changes can go straight to one agent from below the message box.
  • The setup wizard and plan cards now match how Pyloxa works. The welcome page no longer says Pyloxa has no server: your code and agent replies never pass through Pyloxa's servers, and anonymous usage statistics stay off unless you turn them on. The wizard points to the Workflow page instead of the old Routing Rules page. In Pro, plan cards no longer say “at most two at a time”: tasks run as many at once as each connection allows.
  • When the brain can't draft a workflow, Pyloxa says why and what to do next.
  • Interface languages other than Chinese no longer show Chinese punctuation in a few places.
  • In the free version, workflows drafted by the brain never apply automatic mode.

Privacy

  • No new network requests. Pyloxa Help opens pyloxa.com in your browser.
  • The test drive's sample repository stays in Pyloxa's data folder on your computer, under test-drive.

Upgrading

Run the new installer over the old version. Your run history, projects, settings, shared memory and saved API keys in %APPDATA%\Pyloxa are kept. The database stays at version 21, so you can go back to 0.1.10 with the same data; 0.1.10 doesn't show your workflows and can't import dispatch packs that contain them.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Test code that an agent writes still runs outside the sandbox when your verification commands run it, without your keys in its environment. Review the changes of tasks that add or change tests.
  • Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
  • Agent Teams is experimental.
  • Pyloxa Help is in English and Traditional Chinese only for now.
  • Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

0.1.10

Released 2026-11-16

This update opens the Pro preview: sign in and use every Pro feature for free until Pro goes on sale. The free version still needs no account. It also reorganizes navigation and settings, adds six interface languages and adds optional anonymous usage statistics.

Pro preview

  • Sign in to use Pro for free. Choose Sign in in the license section of Settings → General settings or on any Pro lock, and sign in in your browser with Google, GitHub or a code sent to your email. The sidebar shows Pro preview while it lasts.
  • The preview ends when Pro goes on sale. We will tell you at least 30 days before, in the app and by email. After it ends you keep Pro for 14 more days and see the early-bird discount in the app and on your account page. Then the app returns to the free version and keeps your data and settings.
  • What Pro includes: several projects working at once, with one task center for everything waiting on you; decisions within the limits you set (automatic mode); automatic fallbacks when quota runs out; automatic cross-testing; brain fallbacks; Agent Teams (experimental); project priority, per-connection quotas and scheduled plans; a usage dashboard and reports; notifications to Telegram, Discord or a webhook; a skills library synced to every CLI and assigned per project or profile; and routing packs.
  • Two computers per account. Signing in on a third computer asks you to remove one. Your account page at account.pyloxa.com/account lists your computers and lets you rename or remove them, download your data or delete the account.
  • Notices from Pyloxa. When you are signed in, the daily license refresh can bring a short notice from us, such as a change to the preview, shown as a banner at the top of the window. Links in notices only open pyloxa.com or Pyloxa’s GitHub releases. Which notices you dismissed is kept only on your computer.
  • Gifted Pro is shown as such in Settings, the sidebar and the expiry reminders.
  • Works offline for a while. Pyloxa refreshes the license about once a day. If it can't reach the license service, Pro keeps working for 14 days, and from day 3 the sidebar says how many days are left.

Changes

  • Two-level navigation. The sidebar now holds your work: new conversation, task center, run history and conversations. Agents, workflow, commands, skills, memory, connections and appearance are grouped under Settings.
  • Routing Rules is now Workflow. One page shows the whole flow in five steps: planning, phases, division of work, checks and delivery. Dispatch mode, default routing, how plans run, Agent Teams, brain review, cross-testing and automatic fallbacks moved there from Agents & Brain, which now holds only the brain and your profiles. Long explanations moved into help bubbles.
  • Plan cards put results first. When you expand a task, its results and the accept button come before the routing instructions, and you can switch between compact and detailed views.
  • More consistent pages. Settings pages share one header and width, tabs look the same everywhere, tooltips replace browser tooltips, help text is larger, and pages show loading placeholders and empty states.
  • Send with Enter or Ctrl+Enter, your choice. The new-conversation box is centered.
  • The view panel no longer repeats buttons and remembers its tab and width.

New

  • Assignment table. On the Workflow page, choose which agent does each type of work in one table instead of writing simple rules one at a time. Rules for one project or one phase stay in the rules list and still come first, and Pyloxa warns you when a rule without a phase would take over a phase rule.
  • Built-in workflow templates: Balanced (default), Quick fix, Thorough review and Share the quota. Before you apply one, Pyloxa lists what will change, and Undo last template brings your earlier settings back. The flow view, the assignment table and the templates are free; Pro settings in a template aren’t applied in the free version, and the template says so.
  • Six more interface languages: Japanese, Korean, Spanish, Portuguese (Brazil), German and French, for nine in all, the same as pyloxa.com. Pyloxa picks one from your system language, and you can change it in Settings → General settings. The app menu, the tray, notifications and the default rule names are translated too, and the brain can reply in Portuguese (Brazil). The new translations were made with AI and haven’t been reviewed by native speakers yet; tell us when something reads wrong.
  • Arrange the sidebar your way. Drag to resize it or collapse it to icons, pin settings pages you use often, and reorder or hide the items under Work.
  • Find conversations faster. The conversation list is grouped by date, and you can search, pin, archive and right-click conversations.
  • A color for each project.
  • Prompt templates. Type / in the message box to pick a saved prompt; mark the parts you change each time with {{…}}. The free version keeps 5 templates; Pro has no limit.
  • Custom keyboard shortcuts in Settings → Keyboard shortcuts. The app menu follows your choices, and Pyloxa asks before replacing a shortcut that is already in use.
  • Arrange the task center: reorder its sections and choose which ones to show.
  • All layout and display options are free.

Privacy

  • New requests, only after you sign in. Signing in opens your browser at account.pyloxa.com. After that, Pyloxa refreshes its license about once a day, sending only a device ID, a device credential and the Pyloxa and Windows versions. The free version never connects to the license service. Notices from Pyloxa arrive in that same daily refresh, so they add no request of their own.
  • Optional anonymous usage statistics. After the first task you accept, Pyloxa asks once whether to share anonymous usage statistics. It is off unless you turn it on, in Settings → Usage and feedback. When on, Pyloxa sends one report a day to stats.pyloxa.com with counts and categories only, never your prompts, code, file names, paths or account. You can preview each report, reset the anonymous ID or delete your data there.
  • Notifications (Pro) go straight from your computer to the Telegram bot, Discord webhook or HTTPS webhook you set up, with the project name, the event and the plan or task title.
  • The privacy policy has a new section on Pro accounts.

Upgrading

Run the new installer over the old version. Your run history, projects, settings, shared memory and saved API keys in %APPDATA%\Pyloxa are kept. The database stays at version 21, so you can go back to 0.1.9 with the same data.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Test code that an agent writes still runs outside the sandbox when your verification commands run it, without your keys in its environment. Review the changes of tasks that add or change tests.
  • Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
  • Agent Teams is experimental.
  • Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

0.1.9

Released 2026-11-16

This update brings more security fixes, lets agents search and propose shared memories, and changes how many tasks run at once on a Claude Code subscription. Please update from 0.1.8 or earlier.

Security fixes

These come from the same security review as 0.1.7 and 0.1.8. We have no reports of any of them being used.

  • Verification commands wait for you when an agent changes how they run. If a task changes package.json scripts, a Makefile or similar build file, .npmrc, or a file a command names, or if it changes files outside its write scope, Pyloxa doesn't run the verification commands outside the sandbox on its own. The task shows why. After you look at the changes, choose I've reviewed it, run the acceptance commands. Even when they pass, you accept the task yourself.
  • Changes to files that steer agents and automation always need you. When a task changes .claude, .github, .husky, CLAUDE.md or similar files, it is never accepted automatically or handed to brain review, and the merge dialog lists those files again.
  • Trusting a project's agent settings covers more. The trust prompt now also covers scripts those settings point to, hooks folders, skills, agents and commands that widen permissions, Codex hooks, and Gemini CLI policies and extensions. Trust belongs to one project: its worktrees count as the same project, and another repository asks again.
  • **Gemini CLI no longer reads the project's .env.** A .env in a project could send Gemini requests, along with your API key, to another server.
  • Plans can't loosen their own limits. When a plan would start without your approval (fixed mode), Pyloxa checks two limits itself instead of trusting the brain's plan: only implementation and testing phases can skip your approval, and each task's write scope must name a folder or file instead of the whole project. Otherwise the plan waits for your approval and says why.
  • Auto-accepted memories are labelled as such. Agents no longer see them described as approved by you.

Changes

  • One task at a time per Claude Code subscription in a plan. Subscription limits assume normal personal use, so in a plan a Claude Code subscription connection now runs 1 task at a time. Claude Code with an API key, Codex CLI and Gemini CLI still run 2 at a time. The waiting reason on the plan card says so. Tasks you send directly aren't limited, but they count.
  • Pyloxa no longer asks Codex for remaining usage. It no longer starts codex app-server. For a Codex subscription, the usage meter now shows today's tokens, as it does for API keys. When Codex runs out of quota, Pyloxa still marks it as limited.
  • One project at a time in the free version. If another project has work running, a plan you approve waits and starts by itself when that work is done. Choose Do this project first on the plan card to switch; work already running finishes first.
  • Cross-testing and brain reviews take a connection slot. When the connection is busy, they wait their turn instead of running on top of other tasks.
  • The brain doesn't review its own work. If the brain did a task itself, for example a docs task handed to it, its review of that task is marked as not done, and the task waits for you instead of being accepted automatically.
  • No more spell-check underlines. Text boxes no longer put a red underline under misspelled English words. See Privacy for why.

New

  • Agents can use shared memory. While they work, Claude Code, Codex CLI and Gemini CLI can search the memories you've approved and propose new ones, up to 5 per task.
  • The brain can propose memories too. When you tell it something like "always use pnpm from now on", it can offer to remember that. Brain reviews can propose conventions or pitfalls they found.
  • You decide what's remembered. Proposals wait under Pending on the Memory page, with a count in the sidebar, and a conversation shows "The brain wants to remember N things". Accept, edit and accept, or discard each one. No agent sees a proposal until you accept it. For each project you can auto-accept facts and pitfalls that agents propose; rules, preferences, decisions and the brain's proposals always wait for you.
  • Use your memories outside Pyloxa. The Sync to CLIs tab on the Memory page writes a project's rules and preferences into a Pyloxa block in AGENTS.md, adds @AGENTS.md to CLAUDE.md, and can add AGENTS.md to Gemini CLI's context files, so the CLIs see them when you run them in a terminal. You see the diff first and choose the files, and Pyloxa never commits.
  • Optional: the CLIs' user-level memory. Turn on Also write to each CLI's user-level memory (off by default) to keep your rules and preferences for all projects in a Pyloxa block in ~/.claude/CLAUDE.md, ~/.codex/AGENTS.md and ~/.gemini/GEMINI.md. The block updates when your memories change. The original files are backed up before the first write, and turning this off removes the block.
  • Export and import. Export shared memory as Markdown or JSON, and import from a file, choosing what to add.

Fixes

  • Gemini CLI now reads the project's AGENTS.md when Pyloxa runs it, as the other CLIs do.
  • When you import memories, items that look like they contain a key, token or password are marked and can't be selected.
  • Closing the window right after you send a task no longer quits Pyloxa while the task is still starting.

Privacy

  • Two fewer requests: - Pyloxa no longer asks Codex CLI for your remaining usage, so the 10-minute usage checks from 0.1.8 are gone. - Pyloxa no longer downloads a spell-check dictionary from Google. Since 0.1.0, the first launch downloaded an English dictionary (en-US-10-2.bdic) from Google's servers, and the privacy policy didn't list that request. Spell-check is now off, so misspelled English words no longer get a red underline. A dictionary that was already downloaded stays in %APPDATA%\Pyloxa\Dictionaries. You can delete that folder.
  • No new internet requests. This version doesn't connect to any new address on the internet. As before, Pyloxa asks GitHub for the latest version and the CLI compatibility catalog, and the CLIs send your work to their providers.
  • The agent tools stay on your computer. While Pyloxa is open, it listens on random ports on 127.0.0.1 so the agents it starts can reach shared memory. Other computers can't connect. Each task gets its own key, and the key stops working when the task ends.
  • Proposals can come from files an agent read. Check that a proposal makes sense before you accept it.
  • What Pyloxa writes, and only when you choose to. Once you commit AGENTS.md, everyone with access to the repository can read those rules. Each CLI sends the contents of its user-level memory file to its provider when you use that CLI. Backups of the original files are in %APPDATA%\Pyloxa\memory-backup.

Upgrading

Run the new installer over the old version. Your run history, projects, settings, shared memory and saved API keys in %APPDATA%\Pyloxa are kept and upgraded to database version 21 (0.1.8 uses version 12). After upgrading you can't go back to 0.1.8 or earlier with the same data: 0.1.8 won't open the newer database, and it leaves it unchanged, so installing 0.1.9 again brings everything back.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Test code that an agent writes still runs outside the sandbox when your verification commands run it, without your keys in its environment. Review the changes of tasks that add or change tests.
  • Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
  • Gemini CLI connects to the shared memory tools, but searching and proposing haven't been tested with a real Gemini API key yet.
  • Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

0.1.8

Released 2026-11-08

This update adds an agent usage meter and shared memory for all agents, and includes more security fixes. Please update from 0.1.7 or earlier.

New

  • Agent usage meter. The title bar shows how much of each subscription is left: yellow at 70% used, red at 90% or when you're limited. Click it to see each window's usage, its reset time and today's tokens. The cards on the Connections page show the same. Claude Code's numbers come from its own output when it runs; Codex's come from a read-only check (see Privacy). You can turn it off in Settings → Appearance.
  • Shared memory. A new Memory page in the sidebar keeps rules, preferences, decisions and facts for all projects or for one project. Pyloxa adds them to each agent's prompt as background information, not as instructions, and each session shows which memories it used. You can choose Remember on a brain reply or a task session, and import items you pick from the CLIs' own memory files (CLAUDE.md and rules, Claude's auto memory, Codex's AGENTS.md and memories, GEMINI.md). Memories that look like they contain a key, token or password are refused. You can turn memory off entirely or for one project.

Security fixes

These come from the same security review as 0.1.7. We have no reports of any of them being used.

  • Verification commands no longer get your keys. Verification and setup commands run your project's scripts, which agents can change. They no longer receive environment variables that look like keys, such as GITHUB_TOKEN, NPM_TOKEN or AWS keys. If a command really needs one, write NAME=${NAME} in that command's environment variables on the Verification commands page: the value is read from your system when the command runs and is never stored in Pyloxa.
  • A changed worktree pointer stops Pyloxa. If an agent changes the .git pointer in its worktree, Pyloxa now stops instead of running git with another repository's settings outside the agent's sandbox.
  • Keys are masked in run history. Text that looks like a key or token in agent output and command output is masked before it's saved.
  • A tighter interface. Pyloxa's window can't connect to any other address, and it refuses browser permissions other than notifications, the clipboard and local fonts.
  • Official links only in the compatibility catalog. Download and changelog links in the CLI compatibility catalog must point to the official sites, and a catalog dated in the future is ignored.
  • Electron 45.2.3, with the latest Chromium security fixes.

Privacy

  • Usage meter: when Codex is installed and signed in with a subscription, Pyloxa asks Codex CLI for your remaining usage every 10 minutes while Pyloxa is open, and also at startup, after Codex tasks and after your computer wakes. Codex gets the numbers from OpenAI with your own sign-in. This uses none of your quota, and Pyloxa doesn't store your account details. Turning off the usage meter in Settings → Appearance stops these checks. Claude Code's numbers need no extra request.
  • Shared memory is stored only on your computer. Memories are added to the prompts of every agent you use, so a memory you import from one CLI's files also reaches the other agents' providers. Choose what you import.

Upgrading

Run the new installer over the old version. Your run history, projects, settings and saved API keys in %APPDATA%\Pyloxa are kept and upgraded. Shared memory needs a new database version, so after upgrading you can't go back to 0.1.7 or earlier with the same data.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
  • Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

0.1.7

Released 2026-11-06

This is a security update. Please update from 0.1.6 or earlier.

Security fixes

A security review found four problems in Pyloxa 0.1.6 and earlier. We have no reports of any of them being used.

  • Opening a project could run a program from that project. Pyloxa started git and gh by name, and Windows looks in the current folder first. A repository that contained its own git.exe could have that file run as soon as you opened the project in Pyloxa. Pyloxa 0.1.7 starts git, gh and the Windows tools it uses only from where they are installed.
  • A project's agent settings were loaded without asking you. Pyloxa runs Claude Code and Gemini CLI without an interactive window, so their own "Do you trust this folder?" question never appeared. A project's .claude/settings.json, .claude/settings.local.json, .gemini/settings.json or .gemini/.env was loaded whenever work was dispatched, and these files can make the CLI run commands, connect somewhere else or loosen its permissions. Pyloxa 0.1.7 now asks first (see below).
  • **Renaming Pyloxa.exe turned on developer-only options.** With a different file name, Pyloxa treated itself as a development build, which also re-enabled remote debugging that 0.1.6 had blocked. Pyloxa 0.1.7 recognizes a released build by how it is packaged, not by its file name.
  • Pyloxa could be told to show another web page as its interface. Another program already running under your Windows account could start Pyloxa with the ELECTRON_RENDERER_URL environment variable, and that page got the same access as Pyloxa's own interface. Pyloxa 0.1.7 ignores this variable.

Confirming a project's agent settings

When a project you open contains agent settings beyond the model and display options, a notice at the top of the window lists the files. Click a file name to review it, then choose Trust. Until you do, Pyloxa won't dispatch work in that project, and a task that tries explains why.

Pyloxa remembers the exact contents you trusted. If a file changes later, for example after a pull or because an agent's task edited it, Pyloxa asks again. Files that only set the model or display options don't need confirming.

Upgrading

Run the new installer over the old version. Your run history, projects, settings and saved API keys in %APPDATA%\Pyloxa are kept. This version doesn't change the data format.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
  • Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

0.1.6

Released 2026-11-06

This is a security update. Please update from 0.1.5 or earlier.

Security fix

In Pyloxa 0.1.5 and earlier, Pyloxa.exe still accepted three Electron and Node options it doesn't need: Node mode (ELECTRON_RUN_AS_NODE), the NODE_OPTIONS environment variable, and Node's debugging switches (--inspect). Another program already running under your Windows account could use these to run its own code through Pyloxa.exe or attach a debugger to it. We have no reports of this being used.

Pyloxa 0.1.6 closes this:

  • Pyloxa.exe no longer runs in Node mode, ignores NODE_OPTIONS, and ignores Node's debugging switches.
  • If it's started with remote-debugging or similar switches (--remote-debugging-port, --remote-debugging-pipe, --inspect, --js-flags), it quits right away without opening a window or touching your data.
  • It loads only its own app.asar and checks it at startup. If that file has been modified, Pyloxa won't start.

Nothing changes in how you use Pyloxa.

Upgrading

Run the new installer over the old version. Your run history, projects, settings and saved API keys in %APPDATA%\Pyloxa are kept and upgraded. After upgrading, you can't go back to 0.1.5 or earlier with the same data, because older versions can't open the upgraded data folder.

Released 2026-11-06

This release adds a setup wizard for new users, lets a second agent test finished work and the brain review it, keeps Pyloxa running in the tray when you close the window, and lets you resume tasks that were interrupted. Pyloxa also has a new look that you can adjust to your taste.

What's new

### Getting started

  • Setup wizard. New installs start with a wizard. It explains how Pyloxa works and checks for git and Node.js. It installs the agent CLIs with their official npm commands after you confirm, then walks you through sign-in and API keys. Finally you pick the brain (Claude Code or Codex CLI), adjust who does what based on the agents you have, choose your working habits and Skills, and open a project with its verification commands. If you're upgrading, the wizard doesn't appear on its own; open it from Settings → Setup wizard.
  • Getting-started checklist and tips. A checklist in the sidebar and one-time tips help the first time you meet each screen. You can turn tips off or show them again in Settings.
  • Versions in the wizard. The environment check and agent install steps show the latest version, the version Pyloxa has verified, and a one-click update.

### Checking finished work

  • Brain model and effort. Choose the brain's model and thinking effort on the Agents page. This doesn't change the agents that do the work.
  • Brain review. You can have the brain review finished tasks. - Choose off (default), only tasks without verification commands, or all tasks. - The brain can accept the work, ask the same agent for one round of changes, or leave the decision to you. - Work it accepts is labeled as an AI review.
  • Cross-testing. Send a finished task to a different agent to test it; for example, Codex builds and Claude Code tests. - The tester can only add or change test files. - Pyloxa reruns your verification commands itself, and their results take priority over the tester's report. - If the tests fail, you can send the task back to the original agent, which can't change the tester's tests. - Automatic cross-testing by task type or by the brain's judgment is part of the paid version, which isn't available yet.

### Running in the background

  • Keeps working when you close the window. If work is running or scheduled, closing the window leaves Pyloxa in the system tray. - It notifies you when work finishes or needs you. The tray icon shows the status, with a red dot when something needs you. - With nothing running, closing the window quits as before. You can change this in Settings → Background running.
  • Quit when done. Quitting while work is running asks first. - Quit When Done starts nothing new, waits for the running work to finish, then quits. - Quit Now stops the running work and keeps its partial changes.
  • Stays awake while working. While work is running on AC power, Pyloxa keeps the computer from going to sleep when idle. The screen still turns off, and closing the lid or choosing Sleep still works. - Time limits for the brain and for verification commands count only time awake, so waking from sleep doesn't fail a run. - You can turn this off in Settings → Background running.
  • Resume interrupted tasks. If Pyloxa quits, crashes or Windows shuts down while a task runs, you can resume it later: the same agent continues from its changes so far. After a restart, a bar at the top of the window lists interrupted tasks with Resume All.

### Plans and conversations

  • Compact plan cards. Each task collapses to one line: the brain's summary and who it goes to. Details and reassignment are under Details.
  • Report previews. The conversation shows each agent's report and live progress.
  • Concise replies. A switch (off by default) asks the brain and the agents to lead with the conclusion.
  • One worktree for a whole plan. A plan can run its tasks one after another in a single shared worktree, so installed dependencies are kept. You can switch this on the plan card before approving.
  • Fewer confirmations. If a phase has no gate commands and you accepted each of its tasks yourself, it now passes without asking you to approve the phase.

### Gemini CLI and Skills

  • Gemini uses fewer tokens. - On new installs, documentation tasks go to the brain instead of Gemini. Rules you already have aren't changed. - Gemini runs now compress their history earlier and can't start Gemini's built-in sub-agents. - In our tests with Gemini CLI 0.67.0, a one-file edit used about 56,000 tokens.
  • Gemini CLI 0.67.0 verified.
  • Your own Skills folders. You can add your own folders to the Skills inventory. Skills from Claude Code plugins are listed too. Both are read-only.

### Look and feel

  • A new look. Pyloxa now uses its brand indigo by default, with a redesigned sidebar, conversation and Settings page. On Windows it has its own title bar, and on Windows 11 the window can use Mica or Acrylic.
  • Built-in fonts. Inter, JetBrains Mono and Noto Sans TC are included, so text looks the same on every computer. You can also pick any font installed on your computer for English, Chinese and code.
  • Make it yours. In Settings → Appearance you can change the accent color, interface zoom, text size, line spacing, density, corner radius, conversation width, code ligatures and animations, with a live preview.

Privacy and safety

  • A cross-tester works in its own worktree and can change only test files: *.test.*, *.spec.*, and files in test/, tests/ or __tests__/.

Released 2026-11-04

This release fixes a billing safeguard for Gemini CLI 0.66.0 and later. If you use Gemini CLI, please update. It also tells you when your agent CLIs have new versions and can update them for you.

Important: Gemini CLI 0.66.0 and later

Pyloxa runs Gemini CLI only with your own paid Gemini API key, never with a Google account sign-in or Google AI Pro or Ultra subscription. Gemini CLI 0.66.0 changed how it reads system settings, so Pyloxa 0.1.3 and earlier can no longer enforce this. If you signed in to Gemini CLI with a Google account, tasks sent to Gemini could use that sign-in instead of your API key.

Pyloxa 0.1.4 enforces API-key-only auth again:

  • Each Gemini run uses a separate settings folder that Pyloxa creates and deletes afterwards. That folder allows only API-key auth. Your Google sign-in in ~/.gemini is never loaded.
  • If a project's .gemini/settings.json sets a different auth method, Pyloxa won't run Gemini in that project and tells you why.
  • We tested this with Gemini CLI 0.66.0 on a computer whose Gemini settings chose Google sign-in. Pyloxa still used only the API key.

Until you update, don't send tasks to Gemini CLI 0.66.0 or later from Pyloxa 0.1.3 or earlier.

What's new

  • New CLI versions. The Connections page shows when Claude Code, Codex CLI or Gemini CLI has a new version, which version Pyloxa has verified, and a link to the official release notes. A banner tells you when a CLI's version changed since you last opened Pyloxa.
