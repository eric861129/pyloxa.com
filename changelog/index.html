0.1.8

Released 2026-11-08

This update adds an agent usage meter and shared memory for all agents, and includes more security fixes. Please update from 0.1.7 or earlier.

New

  • Agent usage meter. The title bar shows how much of each subscription is left: yellow at 70% used, red at 90% or when you're limited. Click it to see each window's usage, its reset time and today's tokens. The cards on the Connections page show the same. Claude Code's numbers come from its own output when it runs; Codex's come from a read-only check (see Privacy). You can turn it off in Settings → Appearance.
  • Shared memory. A new Memory page in the sidebar keeps rules, preferences, decisions and facts for all projects or for one project. Pyloxa adds them to each agent's prompt as background information, not as instructions, and each session shows which memories it used. You can choose Remember on a brain reply or a task session, and import items you pick from the CLIs' own memory files (CLAUDE.md and rules, Claude's auto memory, Codex's AGENTS.md and memories, GEMINI.md). Memories that look like they contain a key, token or password are refused. You can turn memory off entirely or for one project.

Security fixes

These come from the same security review as 0.1.7. We have no reports of any of them being used.

  • Verification commands no longer get your keys. Verification and setup commands run your project's scripts, which agents can change. They no longer receive environment variables that look like keys, such as GITHUB_TOKEN, NPM_TOKEN or AWS keys. If a command really needs one, write NAME=${NAME} in that command's environment variables on the Verification commands page: the value is read from your system when the command runs and is never stored in Pyloxa.
  • A changed worktree pointer stops Pyloxa. If an agent changes the .git pointer in its worktree, Pyloxa now stops instead of running git with another repository's settings outside the agent's sandbox.
  • Keys are masked in run history. Text that looks like a key or token in agent output and command output is masked before it's saved.
  • A tighter interface. Pyloxa's window can't connect to any other address, and it refuses browser permissions other than notifications, the clipboard and local fonts.
  • Official links only in the compatibility catalog. Download and changelog links in the CLI compatibility catalog must point to the official sites, and a catalog dated in the future is ignored.
  • Electron 45.2.3, with the latest Chromium security fixes.

Privacy

  • Usage meter: when Codex is installed and signed in with a subscription, Pyloxa asks Codex CLI for your remaining usage every 10 minutes while Pyloxa is open, and also at startup, after Codex tasks and after your computer wakes. Codex gets the numbers from OpenAI with your own sign-in. This uses none of your quota, and Pyloxa doesn't store your account details. Turning off the usage meter in Settings → Appearance stops these checks. Claude Code's numbers need no extra request.
  • Shared memory is stored only on your computer. Memories are added to the prompts of every agent you use, so a memory you import from one CLI's files also reaches the other agents' providers. Choose what you import.

Upgrading

Run the new installer over the old version. Your run history, projects, settings and saved API keys in %APPDATA%\Pyloxa are kept and upgraded. Shared memory needs a new database version, so after upgrading you can't go back to 0.1.7 or earlier with the same data.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
  • Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

0.1.7

Released 2026-11-06

This is a security update. Please update from 0.1.6 or earlier.

Security fixes

A security review found four problems in Pyloxa 0.1.6 and earlier. We have no reports of any of them being used.

  • Opening a project could run a program from that project. Pyloxa started git and gh by name, and Windows looks in the current folder first. A repository that contained its own git.exe could have that file run as soon as you opened the project in Pyloxa. Pyloxa 0.1.7 starts git, gh and the Windows tools it uses only from where they are installed.
  • A project's agent settings were loaded without asking you. Pyloxa runs Claude Code and Gemini CLI without an interactive window, so their own "Do you trust this folder?" question never appeared. A project's .claude/settings.json, .claude/settings.local.json, .gemini/settings.json or .gemini/.env was loaded whenever work was dispatched, and these files can make the CLI run commands, connect somewhere else or loosen its permissions. Pyloxa 0.1.7 now asks first (see below).
  • **Renaming Pyloxa.exe turned on developer-only options.** With a different file name, Pyloxa treated itself as a development build, which also re-enabled remote debugging that 0.1.6 had blocked. Pyloxa 0.1.7 recognizes a released build by how it is packaged, not by its file name.
  • Pyloxa could be told to show another web page as its interface. Another program already running under your Windows account could start Pyloxa with the ELECTRON_RENDERER_URL environment variable, and that page got the same access as Pyloxa's own interface. Pyloxa 0.1.7 ignores this variable.

Confirming a project's agent settings

When a project you open contains agent settings beyond the model and display options, a notice at the top of the window lists the files. Click a file name to review it, then choose Trust. Until you do, Pyloxa won't dispatch work in that project, and a task that tries explains why.

Pyloxa remembers the exact contents you trusted. If a file changes later, for example after a pull or because an agent's task edited it, Pyloxa asks again. Files that only set the model or display options don't need confirming.

Upgrading

Run the new installer over the old version. Your run history, projects, settings and saved API keys in %APPDATA%\Pyloxa are kept. This version doesn't change the data format.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
  • Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

0.1.6

Released 2026-11-06

This is a security update. Please update from 0.1.5 or earlier.

Security fix

In Pyloxa 0.1.5 and earlier, Pyloxa.exe still accepted three Electron and Node options it doesn't need: Node mode (ELECTRON_RUN_AS_NODE), the NODE_OPTIONS environment variable, and Node's debugging switches (--inspect). Another program already running under your Windows account could use these to run its own code through Pyloxa.exe or attach a debugger to it. We have no reports of this being used.

Pyloxa 0.1.6 closes this:

  • Pyloxa.exe no longer runs in Node mode, ignores NODE_OPTIONS, and ignores Node's debugging switches.
  • If it's started with remote-debugging or similar switches (--remote-debugging-port, --remote-debugging-pipe, --inspect, --js-flags), it quits right away without opening a window or touching your data.
  • It loads only its own app.asar and checks it at startup. If that file has been modified, Pyloxa won't start.

Nothing changes in how you use Pyloxa.

Upgrading

Run the new installer over the old version. Your run history, projects, settings and saved API keys in %APPDATA%\Pyloxa are kept and upgraded. After upgrading, you can't go back to 0.1.5 or earlier with the same data, because older versions can't open the upgraded data folder.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
  • Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

0.1.5

Released 2026-11-06

This release adds a setup wizard for new users, lets a second agent test finished work and the brain review it, keeps Pyloxa running in the tray when you close the window, and lets you resume tasks that were interrupted. Pyloxa also has a new look that you can adjust to your taste.

What's new

### Getting started

  • Setup wizard. New installs start with a wizard. It explains how Pyloxa works and checks for git and Node.js. It installs the agent CLIs with their official npm commands after you confirm, then walks you through sign-in and API keys. Finally you pick the brain (Claude Code or Codex CLI), adjust who does what based on the agents you have, choose your working habits and Skills, and open a project with its verification commands. If you're upgrading, the wizard doesn't appear on its own; open it from Settings → Setup wizard.
  • Getting-started checklist and tips. A checklist in the sidebar and one-time tips help the first time you meet each screen. You can turn tips off or show them again in Settings.
  • Versions in the wizard. The environment check and agent install steps show the latest version, the version Pyloxa has verified, and a one-click update.

### Checking finished work

  • Brain model and effort. Choose the brain's model and thinking effort on the Agents page. This doesn't change the agents that do the work.
  • Brain review. You can have the brain review finished tasks. - Choose off (default), only tasks without verification commands, or all tasks. - The brain can accept the work, ask the same agent for one round of changes, or leave the decision to you. - Work it accepts is labeled as an AI review.
  • Cross-testing. Send a finished task to a different agent to test it; for example, Codex builds and Claude Code tests. - The tester can only add or change test files. - Pyloxa reruns your verification commands itself, and their results take priority over the tester's report. - If the tests fail, you can send the task back to the original agent, which can't change the tester's tests. - Automatic cross-testing by task type or by the brain's judgment is part of the paid version, which isn't available yet.

### Running in the background

  • Keeps working when you close the window. If work is running or scheduled, closing the window leaves Pyloxa in the system tray. - It notifies you when work finishes or needs you. The tray icon shows the status, with a red dot when something needs you. - With nothing running, closing the window quits as before. You can change this in Settings → Background running.
  • Quit when done. Quitting while work is running asks first. - Quit When Done starts nothing new, waits for the running work to finish, then quits. - Quit Now stops the running work and keeps its partial changes.
  • Stays awake while working. While work is running on AC power, Pyloxa keeps the computer from going to sleep when idle. The screen still turns off, and closing the lid or choosing Sleep still works. - Time limits for the brain and for verification commands count only time awake, so waking from sleep doesn't fail a run. - You can turn this off in Settings → Background running.
  • Resume interrupted tasks. If Pyloxa quits, crashes or Windows shuts down while a task runs, you can resume it later: the same agent continues from its changes so far. After a restart, a bar at the top of the window lists interrupted tasks with Resume All.

### Plans and conversations

  • Compact plan cards. Each task collapses to one line: the brain's summary and who it goes to. Details and reassignment are under Details.
  • Report previews. The conversation shows each agent's report and live progress.
  • Concise replies. A switch (off by default) asks the brain and the agents to lead with the conclusion.
  • One worktree for a whole plan. A plan can run its tasks one after another in a single shared worktree, so installed dependencies are kept. You can switch this on the plan card before approving.
  • Fewer confirmations. If a phase has no gate commands and you accepted each of its tasks yourself, it now passes without asking you to approve the phase.

### Gemini CLI and Skills

  • Gemini uses fewer tokens. - On new installs, documentation tasks go to the brain instead of Gemini. Rules you already have aren't changed. - Gemini runs now compress their history earlier and can't start Gemini's built-in sub-agents. - In our tests with Gemini CLI 0.67.0, a one-file edit used about 56,000 tokens.
  • Gemini CLI 0.67.0 verified.
  • Your own Skills folders. You can add your own folders to the Skills inventory. Skills from Claude Code plugins are listed too. Both are read-only.

### Look and feel

  • A new look. Pyloxa now uses its brand indigo by default, with a redesigned sidebar, conversation and Settings page. On Windows it has its own title bar, and on Windows 11 the window can use Mica or Acrylic.
  • Built-in fonts. Inter, JetBrains Mono and Noto Sans TC are included, so text looks the same on every computer. You can also pick any font installed on your computer for English, Chinese and code.
  • Make it yours. In Settings → Appearance you can change the accent color, interface zoom, text size, line spacing, density, corner radius, conversation width, code ligatures and animations, with a live preview.

Privacy and safety

  • Pyloxa makes no new network requests of its own. The wizard's one-click install runs the CLI's official npm install -g command after you confirm, which downloads from npm.
  • Brain review and cross-testing are off by default. When you turn them on, each reviewed or tested task uses about one more agent run from your own subscription or API key.
  • A cross-tester works in its own worktree and can change only test files: *.test.*, *.spec.*, and files in test/, tests/ or __tests__/.
  • Pyloxa doesn't start with Windows and never blocks sign-out or shutdown. Staying in the tray happens only while work is running or scheduled, unless you choose Always stay in the tray.
  • The built-in fonts ship inside Pyloxa. Nothing is downloaded from Google Fonts or any other font service.

Upgrading

Run the new installer over the old version. Your run history, projects, settings and saved API keys in %APPDATA%\Pyloxa are kept and upgraded. Your routing rules aren't changed. After upgrading, you can't go back to 0.1.4 with the same data, because 0.1.4 can't open the upgraded data folder.

The installer is about 5 MB larger than 0.1.4 because it includes the built-in fonts.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Gemini CLI support is experimental. It can't act as the brain or as a cross-tester, and it can't run commands in unattended mode.
  • Tested with Claude Code 2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.66.0 and 0.67.0.

0.1.4

Released 2026-11-04

This release fixes a billing safeguard for Gemini CLI 0.66.0 and later. If you use Gemini CLI, please update. It also tells you when your agent CLIs have new versions and can update them for you.

Important: Gemini CLI 0.66.0 and later

Pyloxa runs Gemini CLI only with your own paid Gemini API key, never with a Google account sign-in or Google AI Pro or Ultra subscription. Gemini CLI 0.66.0 changed how it reads system settings, so Pyloxa 0.1.3 and earlier can no longer enforce this. If you signed in to Gemini CLI with a Google account, tasks sent to Gemini could use that sign-in instead of your API key.

Pyloxa 0.1.4 enforces API-key-only auth again:

  • Each Gemini run uses a separate settings folder that Pyloxa creates and deletes afterwards. That folder allows only API-key auth. Your Google sign-in in ~/.gemini is never loaded.
  • If a project's .gemini/settings.json sets a different auth method, Pyloxa won't run Gemini in that project and tells you why.
  • We tested this with Gemini CLI 0.66.0 on a computer whose Gemini settings chose Google sign-in. Pyloxa still used only the API key.

Until you update, don't send tasks to Gemini CLI 0.66.0 or later from Pyloxa 0.1.3 or earlier.

What's new

  • New CLI versions. The Connections page shows when Claude Code, Codex CLI or Gemini CLI has a new version, which version Pyloxa has verified, and a link to the official release notes. A banner tells you when a CLI's version changed since you last opened Pyloxa.
  • Update a CLI in one click. When a newer verified version is available, Update to x.y.z runs the CLI's official install command after you confirm: claude install for Claude Code's native install, or npm install -g for npm installs. Pyloxa won't update a CLI while it has tasks running. If Pyloxa can't tell how a CLI was installed, it shows a command you can copy instead.
  • Verified versions update without a new Pyloxa. Pyloxa reads a small compatibility catalog from GitHub with its update check, so newly verified CLI versions, model suggestions and notices reach you without waiting for a Pyloxa release.
  • Skills matrix. The Skills page now shows each skill as a row and each agent as a column, compared against your Skills library in ~/.agents/skills. Each cell shows whether the skill is in sync, installed, different or missing. Click a skill to read its SKILL.md, see its files, or show it in File Explorer.
  • What's new after an update. After you update, a banner links to the changelog on pyloxa.com, and the new-version banner has a See what's new link. The full history is at pyloxa.com/changelog.

Privacy and safety

  • The compatibility catalog is read from GitHub together with the update check, at startup and every 12 hours. Only these two requests are sent, with no project or usage data. Both are turned off by Settings → Notifications and updates.
  • One-click updates change the same CLI you use outside Pyloxa. They only run the official install command shown in the confirmation.
  • Gemini runs in Pyloxa no longer load your own Gemini settings, MCP servers, extensions or hooks, and Gemini's usage statistics are turned off for these runs.
  • In the free version, the Skills page reads skills folders and changes nothing. Adding, syncing, editing and removing skills are part of the paid version, which isn't available yet; those buttons show a lock.

Upgrading

Run the new installer over the old version. Your run history, projects, settings and saved API keys in %APPDATA%\Pyloxa are kept.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates for Pyloxa itself. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Gemini CLI support is experimental. It can't act as the brain and can't run commands in unattended mode. Its built-in sub-agents can use a lot of tokens: in our tests, a one-file task that called a sub-agent used about 340,000 tokens.
  • Tested with Claude Code 2.1.316–2.1.318, Codex CLI 0.166.0 and Gemini CLI 0.42.0 and 0.66.0.

0.1.3

Released 2026-11-04

This release comes from testing Pyloxa on two real projects, a .NET API and a React web app. It fixes what got in the way of real work.

What's new

  • Agents can check their own work. Claude Code can now run the commands you approved under Verification commands, such as installing dependencies, building or testing, before it reports back. Other commands are still refused automatically. Before, every command was refused, so agents had to write code without running it.
  • Suggestions for .NET, Gradle and Maven projects. The Verification commands page now suggests dotnet build for a solution and a dotnet test for each test project. For Java it suggests your project's Gradle or Maven wrapper.
  • Environment variables for verification commands. A command can set variables such as a snapshot-update flag. Pyloxa refuses names that look like keys or passwords and won't override system variables such as PATH.
  • A heads-up for .NET projects on Windows. On Windows, Codex's sandbox can't restore NuGet packages, so it can't build .NET projects. When a .NET task goes to Codex, the plan preview says so. One click makes Claude Code handle backend work in that project, with Codex as the fallback.
  • Flaky checks get a second chance. When a phase's gate checks fail, Pyloxa first runs them once more on the same version. It only asks an agent to fix things if they fail again.

Fixes

  • Long paths on Windows. Approving a plan no longer fails with "Filename too long" in projects with deep folders. Pyloxa's worktree folders also have shorter names now.
  • Clearer git errors. Git errors now show the actual cause instead of progress output. If approving a plan fails, the error stays on the plan card.
  • Verification record headings. In pull requests, long goals are no longer cut off in the middle of parentheses, and agent names aren't repeated.

Privacy and safety

  • The commands an agent may run are exactly the ones you approved under Verification commands. Pyloxa already runs them in the same worktree when it checks results, so this doesn't give agents any new access.
  • Environment variables are stored with the command on your computer. Don't put secrets in them.

Upgrading

Run the new installer over the old version. Your run history, projects and settings in %APPDATA%\Pyloxa are kept. Plans that are already running keep their current worktree folders.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates. Pyloxa tells you when a new version is out.
  • Codex runs through codex exec in its sandbox. On Windows, the sandbox usually can't build projects or install packages, so Codex's results are checked by your verification commands.
  • Gemini CLI support is experimental. It can't act as the brain and can't run commands in unattended mode.
  • Tested with Claude Code 2.1.316–2.1.317, Codex CLI 0.166.0 and Gemini CLI 0.42.0.

0.1.2

Released 2026-11-04

Three agents work together out of the box, Gemini CLI joins as an experimental option, and a plan can run two tasks at once.

What's new

  • A default flow for three agents. New installs start with Claude Code as the brain, handling frontend work and video editing; Codex handling backend work and image generation; and Gemini handling writing and docs. If an agent isn't set up, its tasks go to the brain, and the plan preview says why. Every rule can be changed or deleted on the Routing rules page. If you already use Pyloxa, click Apply the default flow there; your existing rules are kept.
  • Gemini CLI (experimental). Connect Gemini CLI with your own paid Gemini API key on the Connections page. Google account sign-in and AI Pro or Ultra subscriptions are not supported. Pyloxa makes Gemini CLI use only your API key, even if your own Gemini settings choose Google sign-in. Gemini runs tasks but can't act as the brain.
  • Two tasks at once. A plan runs up to two independent tasks at the same time, and each CLI runs at most two tasks at once. Tasks that change the same files wait for each other, and the plan card shows what a task is waiting for.
  • A guided first task. New conversations suggest a small first task and explain the steps. If the folder isn't a git project or has no commits yet, the plan preview says so before you approve.
  • Update notice and desktop notifications. Pyloxa tells you when a new version is out. When Pyloxa isn't in front, Windows notifications tell you when a plan is ready, a task needs you, work finishes or fails, the brain replies, or a CLI runs out of quota. Both can be turned off in Settings.
  • Fewer version warnings. Patch versions in the same series as a tested version, such as Claude Code 2.1.x, no longer show an "unverified version" warning.
  • Verification record in pull requests. When you create a pull request, Pyloxa can append what each agent result actually went through: acceptance commands, required files, write scope, phase checks and who approved them. Checks that didn't run are never shown as passed.
  • Skills inventory. A new Skills page lists the skills each CLI can read and flags skills with the same name but different content.
  • Team rules in the repository. Pyloxa reads .pyloxa/rules.json and .pyloxa/commands.json from a project. You see a preview first; rules apply to the project only when you choose, and commands still need your approval one by one.
  • Usage and feedback. Settings shows your first success, completion rate, fallbacks and other counts, computed on your computer only. Copy diagnostics copies versions and counts for a bug report.

Privacy

  • Pyloxa asks GitHub for the latest Pyloxa version at startup and every 12 hours. Only this request is sent, with no project or usage data. Turn it off in Settings → Notifications and updates.
  • The Skills page reads the skills folders of each CLI (~/.agents/skills, ~/.claude/skills, ~/.codex/skills, ~/.gemini/skills) and of the open project. It reads nothing else in those CLI folders and changes nothing.
  • Usage statistics are computed on your computer and never sent. Diagnostics contain no project names, paths, instructions, code, accounts or keys, and leave your computer only if you paste them somewhere.

Upgrading

Run the new installer over the old version. Your run history and projects in %APPDATA%\Pyloxa are kept. Existing setups don't get the default flow automatically; use Apply the default flow on the Routing rules page if you want it.

Known limitations

  • Windows 10 and 11, 64-bit only.
  • The installer is not code-signed. SmartScreen may warn you; choose More info, then Run anyway.
  • No automatic updates. Pyloxa tells you when a new version is out; download it from the releases page.
  • Codex runs through codex exec inside its sandbox and cannot ask for approval of single actions.
  • Gemini CLI support is experimental. It can't act as the brain or resume a previous session. In unattended mode Gemini CLI offers no shell tool, so Gemini can edit files but can't run commands.
  • Tested with Claude Code 2.1.316–2.1.317, Codex CLI 0.166.0 and Gemini CLI 0.42.0. Other patch versions in the same series run without a warning; a new series runs in supervised mode only, and its output format can change.
  • Running two tasks at once is new. It has been tested with Claude Code and Codex CLI; if you see anything odd, please report it.

0.1.1

Released 2026-11-03

Easier first run, and you can now use your own API key instead of a subscription.

What's new

  • Getting started guide. If no agent CLI is ready, the home screen and the conversation show what to install, the official sign-in command to copy into a terminal (claude auth login or codex login), and re-detect when you come back to Pyloxa.
  • API key connections. On the Connections page, switch Claude Code or Codex to your own API key. Usage is billed per use to your API account instead of your subscription. Pyloxa encrypts the key with Windows secure storage (DPAPI), passes it only to the CLI process that runs your work, and shows only the last 4 characters. Switching back to your subscription deletes the saved key.
  • Clearer connection problems. The sidebar, the agent settings and the conversation now show the problem that actually blocks work, for example "not signed in" instead of "unverified version".
  • Re-detect finds newly installed CLIs. Pyloxa reads PATH again when it re-detects, so you don't have to restart it after installing a CLI.
  • When the brain can't run. A notice above the message box explains why and links to the fix. A message that couldn't be sent stays visible with the reason.

Upgrading

Run the new installer over the old version. Your run history and projects in %APPDATA%\Pyloxa are kept.

Released 2026-11-03

The first free release of Pyloxa for Windows.

What it does

  • One conversation. Tell the brain (Claude Code or Codex) what you want. It reads the project, asks when something is unclear, and answers directly or proposes a plan of phases and tasks.
  • Routing rules. Your rules decide which agent gets each task. Every task shows the rule it matched, why, and its fallback. The rules page can simulate routing without calling an agent.
  • Isolated work. Each writable task runs in its own git worktree. Pyloxa never stashes, resets or checks out your working directory.
  • Verification commands. Approve commands such as npm run test, try them first, and let tasks run them. A task that passes all its checks and needs no review is accepted for you; a task that fails gets one automatic fix.
  • Phase gates. At the end of each phase, the gate commands run on the integrated result. The plan moves on by itself or waits for your approval; a failed gate gets one automatic fix task.
  • When quota runs out. If a CLI reports its usage limit, Pyloxa marks that connection as limited with the reset time and stops sending it work. You confirm a fallback agent, which continues from the previous agent's files, or let Pyloxa retry after the reset. Rate limits and network errors are retried once.
  • Usage. Token usage for each task and for the whole plan.
  • Restart recovery. If Pyloxa stops in the middle of a task, it stops the leftover CLI process on the next start, keeps the work done so far and asks you to review it.
  • Workspace. Browse and search files, edit Markdown with a live preview, review diffs, commit, branch, push and pull, and open pull requests through gh.
  • Languages and themes. English, 繁體中文 and 简体中文, with light, dark and color themes.
