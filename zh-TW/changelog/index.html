0.1.7

發布於 2026-11-06

這是一個安全性更新，請從 0.1.6 以前的版本更新。

安全性修正

安全審查在 Pyloxa 0.1.6 以前的版本找到四個問題，目前沒有收到任何一個被利用的回報。

  • 開啟專案時可能執行專案裡的程式。 Pyloxa 以名稱啟動 git 與 gh，而 Windows 會先在目前的資料夾裡找。如果 repo 裡放了自己的 git.exe，你在 Pyloxa 開啟這個專案時，它就可能被執行。Pyloxa 0.1.7 只從安裝位置啟動 git、gh 與它用到的 Windows 工具。
  • 專案的 Agent 設定檔沒有先問過你就被載入。 Pyloxa 在沒有互動視窗的模式下執行 Claude Code 與 Gemini CLI，所以它們自己的「信任這個資料夾嗎？」不會出現。專案裡的 .claude/settings.json、.claude/settings.local.json、.gemini/settings.json 或 .gemini/.env 會在派工時被載入，而這些檔案可以讓 CLI 執行命令、連到其他地方，或放寬它的權限。Pyloxa 0.1.7 會先問你（見下方說明）。
  • **把 Pyloxa.exe 改名，會打開只供開發用的選項。** 換了檔名之後，Pyloxa 會把自己當成開發版，連 0.1.6 擋下的遠端除錯也會重新可用。Pyloxa 0.1.7 改以打包方式判斷是不是正式版，不看檔名。
  • Pyloxa 可能被要求把其他網頁當成它的介面。 已經在你的 Windows 帳號下執行的其他程式，可以帶著 ELECTRON_RENDERER_URL 環境變數啟動 Pyloxa，那個網頁會拿到和 Pyloxa 介面相同的權限。Pyloxa 0.1.7 不再理會這個變數。

確認專案的 Agent 設定檔

你開啟的專案裡如果有模型與顯示選項以外的 Agent 設定，視窗上方會出現提示並列出這些檔案。按檔名可以檢查內容，確認後按「信任」。在那之前，Pyloxa 不會在這個專案派工，嘗試派工時也會說明原因。

Pyloxa 記住的是你信任時的檔案內容。之後檔案有變動（例如 pull 之後，或 Agent 的工作修改了它），Pyloxa 會再問一次。只設定模型或顯示選項的檔案不需要確認。

升級

直接執行新的安裝檔覆蓋舊版即可。存在 %APPDATA%\Pyloxa 的執行紀錄、專案、設定與保存的 API Key 都會保留。這個版本沒有改變資料格式。

已知限制

  • 只支援 Windows 10 與 11（64 位元）。
  • 安裝檔沒有程式碼簽章，SmartScreen 可能跳出警告；請按「其他資訊」，再按「仍要執行」。
  • Pyloxa 本身不會自動更新。有新版本時 Pyloxa 會提示你。
  • Codex 透過 codex exec 在它的沙箱內執行。在 Windows 上，這個沙箱通常無法建置專案或安裝套件，所以 Codex 的成果以你的驗證命令驗收。
  • Gemini CLI 是實驗性支援：不能擔任大腦或交叉測試的測試者，在無人值守模式下也不能執行命令。
  • 已測試 Claude Code 2.1.318、Codex CLI 0.166.0，以及 Gemini CLI 0.66.0 與 0.67.0。

0.1.6

發布於 2026-11-06

這是一個安全性更新，請從 0.1.5 以前的版本更新。

安全性修正

Pyloxa 0.1.5 以前的 Pyloxa.exe 還接受三個它用不到的 Electron 與 Node 選項：Node 模式（ELECTRON_RUN_AS_NODE）、NODE_OPTIONS 環境變數，以及 Node 的除錯參數（--inspect）。已經在你的 Windows 帳號下執行的其他程式，可以藉此透過 Pyloxa.exe 執行它自己的程式碼，或掛上除錯器。目前沒有收到被利用的回報。

Pyloxa 0.1.6 關掉了這些途徑：

  • Pyloxa.exe 不再以 Node 模式執行，也不理會 NODE_OPTIONS 與 Node 的除錯參數。
  • 帶著遠端除錯之類的參數（--remote-debugging-port、--remote-debugging-pipe、--inspect、--js-flags）啟動時，會直接結束，不開視窗、也不碰你的資料。
  • 只載入它自己的 app.asar，並在啟動時檢查；這個檔案被改過時，Pyloxa 不會啟動。

使用方式完全不變。

0.1.5

發布於 2026-11-06

這一版加入新使用者的設定精靈。完成的工作可以交給另一個 Agent 測試、交給大腦驗收。關閉視窗時 Pyloxa 會留在系統匣繼續執行，被中斷的工作也可以接續。外觀也換新了，而且可以依你的習慣調整。

新功能

### 開始使用

  • 設定精靈：新安裝時會先出現設定精靈。 - 精靈會說明 Pyloxa 怎麼運作，並檢查 git 與 Node.js。 - 你確認後，它用官方的 npm 命令安裝 Agent CLI，再帶你完成登入與金鑰。 - 接著選大腦（Claude Code 或 Codex CLI），依你有的 Agent 調整分工，設定工作習慣與 Skills，最後開啟專案並核准驗證命令。 - 從舊版升級不會自動出現，可以在「設定 → 設定精靈」開啟。
  • 入門清單與提示：側欄有入門清單；第一次碰到某個畫面時會出現一則提示，可以在「設定」關閉或重新顯示。
  • 精靈顯示版本：環境檢查與安裝 Agent 會顯示最新版本、Pyloxa 已驗證到的版本，並提供一鍵更新。

### 檢查完成的工作

  • 大腦的模型與思考強度：可以在「Agent」頁設定大腦的模型與思考強度，不影響執行工作的 Agent。
  • 大腦驗收：可以讓大腦驗收完成的工作。 - 可以選關閉（預設）、只驗收沒有驗證命令的工作，或驗收所有工作。 - 大腦可以接受、請同一個 Agent 修改一次，或交給你決定。 - 大腦接受的工作會標示「AI 驗收」。
  • 交叉測試：完成的工作可以交給另一個 Agent 測試，例如 Codex 開發、Claude Code 測試。 - 測試者只能新增或修改測試檔。 - Pyloxa 會自己重跑你的驗證命令，以命令結果為準。 - 沒通過時，可以交回原本的 Agent 修正，而且它不能改測試者寫的測試。 - 依工作類型或由大腦判斷的自動交叉測試屬於付費版，目前還沒推出。

### 背景執行

  • 關閉視窗後繼續執行：有工作在執行或排定時，關閉視窗後 Pyloxa 會留在系統匣。 - 工作完成或需要你處理時會通知你。系統匣圖示會顯示狀態，有事等你時帶紅點。 - 沒有工作時，關閉視窗照常結束。可以在「設定 → 背景執行」修改。
  • 做完再結束：有工作在執行時，結束 Pyloxa 會先問你。 - 「做完再結束」不再開始新的工作，等執行中的做完後自動結束。 - 「立即結束」會停止執行中的工作，改到一半的內容會保留。
  • 執行中不睡眠：有工作在執行、接上電源時，Pyloxa 會讓電腦不因閒置而睡眠。螢幕照常關閉，闔上螢幕或手動睡眠也照常。 - 大腦與驗證命令的時間上限只算醒著的時間，電腦睡醒後不會因此判定逾時。 - 可以在「設定 → 背景執行」關閉。
  • 接續中斷的工作：Pyloxa 結束、當掉或 Windows 關機時還在執行的工作，之後可以接續，由同一個 Agent 從中斷前的成果接著做。重新開啟後，視窗頂端會列出中斷的工作，可以「全部接續」。

### 計畫與對話

  • 計畫卡收合：每個工作收合成一行，顯示大腦寫的摘要與交給誰；細節與改派放在「詳細」。
  • 回報預覽：對話中可以直接看到 Agent 的回報預覽與執行中的動態。
  • 精簡回覆：開啟這個開關（預設關閉）後，大腦與 Agent 的回覆會先講結論。
  • 整個計畫共用一個 worktree：計畫可以在同一個 worktree 依序執行所有工作，保留已安裝的依賴。核准前可以在計畫卡上切換。
  • 更少的確認：階段沒有 Gate 命令、而且工作都由你逐一接受過時，這個階段會直接通過，不用再核准。

### Gemini CLI 與 Skills

  • Gemini 用量下降： - 新安裝時，文章與文件改交給大腦，不再交給 Gemini；你已有的規則不受影響。 - Gemini 執行時會提早壓縮對話紀錄，也不能啟動 Gemini 內建的子 Agent。 - 我們用 Gemini CLI 0.67.0 測試時，一個單檔修改用了約 5.6 萬 token。
  • Gemini CLI 0.67.0 已驗證。
  • 自訂 Skills 資料夾：Skills 盤點可以加入你自己的資料夾，也會列出 Claude Code 外掛的 Skills，兩者都只讀。

### 外觀

  • 新的外觀：預設改用品牌的 Pyloxa 靛藍，側欄、對話與設定頁都重新設計。Windows 上改用 Pyloxa 自己的標題列，Windows 11 的視窗可以使用 Mica 或 Acrylic 材質。
  • 內建字型：內建 Inter、JetBrains Mono 與思源黑體，每台電腦看起來都一樣；英文、中文與程式碼也可以改用你電腦上已安裝的任何字型。
  • 依你的習慣調整：在「設定 → 外觀」可以調整強調色、介面縮放、字級、行距、密度、圓角、對話寬度、程式碼連字與動畫，並即時預覽。

隱私與安全

  • Pyloxa 本身沒有增加新的網路請求。設定精靈的一鍵安裝會在你確認後，執行 CLI 官方的 npm install -g 命令，由 npm 下載。
  • 大腦驗收與交叉測試預設關閉；開啟後，每個被驗收或測試的工作大約多用一次你自己的訂閱或 API Key 的 Agent 執行。
  • 交叉測試的測試者在自己的 worktree 工作，只能修改測試檔：*.test.*、*.spec.*，以及 test/、tests/、__tests__/ 資料夾裡的檔案。
  • Pyloxa 不會隨 Windows 啟動，也不會擋住登出或關機。只有在有工作執行或排定時才會留在系統匣，除非你選「一律留在系統匣」。
  • 內建字型都包含在 Pyloxa 裡，不會向 Google Fonts 或其他字型服務下載。

升級

因為內建字型，安裝檔比 0.1.4 大約多 5 MB。

0.1.4

發布於 2026-11-04

這一版修正 Gemini CLI 0.66.0 以後的費用保護；如果你有用 Gemini CLI，請更新。另外，Agent CLI 有新版本時 Pyloxa 會告訴你，也可以幫你更新。

重要：Gemini CLI 0.66.0 以後的版本

Pyloxa 只用你自己的付費 Gemini API Key 執行 Gemini CLI，不使用 Google 帳號登入，也不使用 Google AI Pro 或 Ultra 訂閱。Gemini CLI 0.66.0 改變了讀取系統設定的方式，Pyloxa 0.1.3 以前的版本因此無法再強制這一點：如果你在 Gemini CLI 用 Google 帳號登入過，交給 Gemini 的工作可能改用那個登入，而不是你的 API Key。

Pyloxa 0.1.4 重新強制只用 API Key：

  • 每次執行 Gemini 都使用 Pyloxa 另外建立、執行完就刪除的設定資料夾，只允許 API Key 認證。你在 ~/.gemini 的 Google 登入不會被載入。
  • 專案的 .gemini/settings.json 指定了其他認證方式時，Pyloxa 不會在這個專案執行 Gemini，並說明原因。
  • 我們用 Gemini CLI 0.66.0，在 Gemini 設定選了 Google 帳號登入的電腦上測試過：Pyloxa 仍然只用 API Key。

更新之前，請不要從 Pyloxa 0.1.3 以前的版本把工作交給 Gemini CLI 0.66.0 以後的版本。

新功能

  • CLI 的新版本：「連線」頁會顯示 Claude Code、Codex CLI 或 Gemini CLI 有新版本、Pyloxa 驗證到哪一版，並連到官方的更新說明。CLI 的版本和上次開啟 Pyloxa 時不同時，會有一則提示。
  • 一鍵更新 CLI：有更新的已驗證版本時，按「更新到 x.y.z」並確認後，Pyloxa 會執行該 CLI 官方的安裝命令：原生安裝的 Claude Code 用 claude install，npm 安裝的用 npm install -g。CLI 有工作在執行時不會更新。Pyloxa 判斷不出安裝方式時，改為顯示可以複製的命令。
  • 已驗證版本不必等 Pyloxa 發新版：Pyloxa 查詢新版本時會一起向 GitHub 讀取一份小小的相容性目錄，新驗證的 CLI 版本、模型建議與公告不必等 Pyloxa 發新版就能送到你手上。
  • Skills 矩陣：「Skills」頁改成每一列是一個 Skill、每一欄是一個 Agent，以 ~/.agents/skills 的 Skills 庫為基準比對；每一格標示已同步、已安裝、內容不同或沒有。點 Skill 可以閱讀它的 SKILL.md、查看資料夾內的檔案，或在檔案總管中顯示。
  • 更新後看看改了什麼：更新後會有一則提示連到 pyloxa.com 的改版紀錄，新版本提示也多了「看看改了什麼」。完整紀錄在 pyloxa.com/zh-TW/changelog。

隱私與安全

  • 相容性目錄和新版本查詢一起向 GitHub 讀取，在啟動時和每 12 小時各一次；只送出這兩個查詢，不含任何專案或使用資料。兩者都可以在「設定 → 通知與更新」關閉。
  • 一鍵更新改的是你在 Pyloxa 以外也在用的同一個 CLI，只會執行確認視窗上顯示的官方安裝命令。
  • 在 Pyloxa 執行的 Gemini 不再載入你自己的 Gemini 設定、MCP 伺服器、擴充與 hooks，這些執行也會關閉 Gemini 的使用統計。
  • 免費版的「Skills」頁只讀取 Skills 資料夾，不做任何修改。新增、同步、編輯與移除 Skill 屬於付費版，目前還沒推出，這些按鈕會顯示鎖頭。

新功能

  • Agent 可以自己確認成果：Claude Code 現在可以執行你在「驗證命令」核准的命令，例如安裝依賴、建置、測試，先確認再回報；其他命令照樣自動拒絕。以前所有命令都被拒絕，Agent 只能寫程式、不能執行。
  • .NET、Gradle 與 Maven 專案的命令建議：「驗證命令」頁會為方案建議 dotnet build，並為每個測試專案各建議一個 dotnet test；Java 專案則建議使用專案自己的 Gradle 或 Maven wrapper。
  • 驗證命令可以設定環境變數：例如重新產生快照的旗標。名稱看起來像金鑰或密碼的變數不會被儲存，也不能覆寫 PATH 等系統變數。
  • Windows 上 .NET 專案的提醒：Windows 上 Codex 的沙箱無法還原 NuGet 套件，所以無法建置 .NET 專案。.NET 的工作派給 Codex 時，計畫預覽會說明這一點；按一下就能讓這個專案的後端工作改由 Claude Code 負責，Codex 留作備援。
  • 不穩定的檢查會再跑一次：階段的 Gate 檢查沒通過時，Pyloxa 會先在同一個版本上再跑一次，仍然沒過才請 Agent 修正。

修正

  • Windows 長路徑：資料夾很深的專案，核准計畫時不再出現「Filename too long」。Pyloxa 的 worktree 資料夾名稱也縮短了。
  • git 錯誤更清楚：git 錯誤會顯示真正的原因，不再被進度輸出蓋過。核准計畫失敗時，錯誤會留在計畫卡上。
  • 驗證紀錄的標題：在 pull request 裡，很長的目標不再從括號中間截斷，Agent 名稱也不再重複。

隱私與安全

  • Agent 能執行的命令，就是你在「驗證命令」核准的那些。Pyloxa 驗收成果時本來就會在同一個 worktree 執行這些命令，所以 Agent 並沒有多出新的權限。
  • 環境變數和命令一起存在你的電腦上，請不要放入金鑰或密碼。

升級

直接執行新的安裝檔覆蓋舊版即可。存在 %APPDATA%\Pyloxa 的執行紀錄、專案與設定都會保留。已經在執行的計畫會沿用原本的 worktree 資料夾。

功能

  • 一段對話：告訴大腦（Claude Code 或 Codex）你想做什麼。它會先讀過專案，不清楚時先發問，再直接回答或提出分成階段與工作的計畫。

  • 階段 Gate：每個階段結束時，在整合後的成果上執行 Gate 命令。計畫會自動往下走，或等你核准；Gate 沒通過時會自動新增一個修正工作。
  • 額度用盡時：CLI 回報用量上限時，Pyloxa 會把那個連線標為受限、顯示重設時間，並停止派工給它。你可以確認由備援 Agent 從前一個 Agent 的成果接著做，或等額度恢復後自動重試。限流與網路錯誤會自動重試一次。
  • 用量：每個工作與整個計畫的 token 用量。
  • 重啟核對：如果 Pyloxa 在工作進行中結束，下次啟動時會停止殘留的 CLI 程序、保留已完成的部分，並請你核對。
  • 工作區：瀏覽與搜尋檔案、編輯 Markdown 並即時預覽、查看差異、提交、分支、推送與拉取，並透過 gh 開 pull request。
  • 語言與主題：English、繁體中文、简体中文，以及淺色、深色與多種色彩主題。
