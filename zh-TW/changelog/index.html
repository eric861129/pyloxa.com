0.1.4

發布於 2026-11-04

這一版修正 Gemini CLI 0.66.0 以後的費用保護；如果你有用 Gemini CLI，請更新。另外，Agent CLI 有新版本時 Pyloxa 會告訴你，也可以幫你更新。

重要：Gemini CLI 0.66.0 以後的版本

Pyloxa 只用你自己的付費 Gemini API Key 執行 Gemini CLI，不使用 Google 帳號登入，也不使用 Google AI Pro 或 Ultra 訂閱。Gemini CLI 0.66.0 改變了讀取系統設定的方式，Pyloxa 0.1.3 以前的版本因此無法再強制這一點：如果你在 Gemini CLI 用 Google 帳號登入過，交給 Gemini 的工作可能改用那個登入，而不是你的 API Key。

Pyloxa 0.1.4 重新強制只用 API Key：

  • 每次執行 Gemini 都使用 Pyloxa 另外建立、執行完就刪除的設定資料夾，只允許 API Key 認證。你在 ~/.gemini 的 Google 登入不會被載入。
  • 專案的 .gemini/settings.json 指定了其他認證方式時，Pyloxa 不會在這個專案執行 Gemini，並說明原因。
  • 我們用 Gemini CLI 0.66.0，在 Gemini 設定選了 Google 帳號登入的電腦上測試過：Pyloxa 仍然只用 API Key。

更新之前，請不要從 Pyloxa 0.1.3 以前的版本把工作交給 Gemini CLI 0.66.0 以後的版本。

新功能

  • CLI 的新版本：「連線」頁會顯示 Claude Code、Codex CLI 或 Gemini CLI 有新版本、Pyloxa 驗證到哪一版，並連到官方的更新說明。CLI 的版本和上次開啟 Pyloxa 時不同時，會有一則提示。
  • 一鍵更新 CLI：有更新的已驗證版本時，按「更新到 x.y.z」並確認後，Pyloxa 會執行該 CLI 官方的安裝命令：原生安裝的 Claude Code 用 claude install，npm 安裝的用 npm install -g。CLI 有工作在執行時不會更新。Pyloxa 判斷不出安裝方式時，改為顯示可以複製的命令。
  • 已驗證版本不必等 Pyloxa 發新版：Pyloxa 查詢新版本時會一起向 GitHub 讀取一份小小的相容性目錄，新驗證的 CLI 版本、模型建議與公告不必等 Pyloxa 發新版就能送到你手上。
  • Skills 矩陣：「Skills」頁改成每一列是一個 Skill、每一欄是一個 Agent，以 ~/.agents/skills 的 Skills 庫為基準比對；每一格標示已同步、已安裝、內容不同或沒有。點 Skill 可以閱讀它的 SKILL.md、查看資料夾內的檔案，或在檔案總管中顯示。
  • 更新後看看改了什麼：更新後會有一則提示連到 pyloxa.com 的改版紀錄，新版本提示也多了「看看改了什麼」。完整紀錄在 pyloxa.com/zh-TW/changelog。

隱私與安全

  • 相容性目錄和新版本查詢一起向 GitHub 讀取，在啟動時和每 12 小時各一次；只送出這兩個查詢，不含任何專案或使用資料。兩者都可以在「設定 → 通知與更新」關閉。
  • 一鍵更新改的是你在 Pyloxa 以外也在用的同一個 CLI，只會執行確認視窗上顯示的官方安裝命令。
  • 在 Pyloxa 執行的 Gemini 不再載入你自己的 Gemini 設定、MCP 伺服器、擴充與 hooks，這些執行也會關閉 Gemini 的使用統計。
  • 免費版的「Skills」頁只讀取 Skills 資料夾，不做任何修改。新增、同步、編輯與移除 Skill 屬於付費版，目前還沒推出，這些按鈕會顯示鎖頭。

升級

直接執行新的安裝檔覆蓋舊版即可。存在 %APPDATA%\Pyloxa 的執行紀錄、專案、設定與保存的 API Key 都會保留。

已知限制

  • 只支援 Windows 10 與 11（64 位元）。
  • 安裝檔沒有程式碼簽章，SmartScreen 可能跳出警告；請按「其他資訊」，再按「仍要執行」。
  • Pyloxa 本身不會自動更新。有新版本時 Pyloxa 會提示你。
  • Codex 透過 codex exec 在它的沙箱內執行。在 Windows 上，這個沙箱通常無法建置專案或安裝套件，所以 Codex 的成果以你的驗證命令驗收。
  • Gemini CLI 是實驗性支援：不能擔任大腦，在無人值守模式下也不能執行命令。它內建的子 Agent 可能用掉很多 token：我們測試時，一個呼叫了子 Agent 的單檔工作用了約 34 萬 token。
  • 已測試 Claude Code 2.1.316–2.1.318、Codex CLI 0.166.0，以及 Gemini CLI 0.42.0 與 0.66.0。

0.1.3

發布於 2026-11-04

這一版來自在兩個真實專案（一個 .NET API、一個 React 網頁）上實測 Pyloxa，修正了實際工作時卡住的地方。

新功能

  • Agent 可以自己確認成果：Claude Code 現在可以執行你在「驗證命令」核准的命令，例如安裝依賴、建置、測試，先確認再回報；其他命令照樣自動拒絕。以前所有命令都被拒絕，Agent 只能寫程式、不能執行。
  • .NET、Gradle 與 Maven 專案的命令建議：「驗證命令」頁會為方案建議 dotnet build，並為每個測試專案各建議一個 dotnet test；Java 專案則建議使用專案自己的 Gradle 或 Maven wrapper。
  • 驗證命令可以設定環境變數：例如重新產生快照的旗標。名稱看起來像金鑰或密碼的變數不會被儲存，也不能覆寫 PATH 等系統變數。
  • Windows 上 .NET 專案的提醒：Windows 上 Codex 的沙箱無法還原 NuGet 套件，所以無法建置 .NET 專案。.NET 的工作派給 Codex 時，計畫預覽會說明這一點；按一下就能讓這個專案的後端工作改由 Claude Code 負責，Codex 留作備援。
  • 不穩定的檢查會再跑一次：階段的 Gate 檢查沒通過時，Pyloxa 會先在同一個版本上再跑一次，仍然沒過才請 Agent 修正。

修正

  • Windows 長路徑：資料夾很深的專案，核准計畫時不再出現「Filename too long」。Pyloxa 的 worktree 資料夾名稱也縮短了。
  • git 錯誤更清楚：git 錯誤會顯示真正的原因，不再被進度輸出蓋過。核准計畫失敗時，錯誤會留在計畫卡上。
  • 驗證紀錄的標題：在 pull request 裡，很長的目標不再從括號中間截斷，Agent 名稱也不再重複。

隱私與安全

  • Agent 能執行的命令，就是你在「驗證命令」核准的那些。Pyloxa 驗收成果時本來就會在同一個 worktree 執行這些命令，所以 Agent 並沒有多出新的權限。
  • 環境變數和命令一起存在你的電腦上，請不要放入金鑰或密碼。

直接執行新的安裝檔覆蓋舊版即可。存在 %APPDATA%\Pyloxa 的執行紀錄、專案與設定都會保留。已經在執行的計畫會沿用原本的 worktree 資料夾。

0.1.2

發布於 2026-11-04

三個 Agent 一裝好就能分工，Gemini CLI 以實驗性功能加入，計畫也可以同時執行兩個工作。

新功能

  • 三個 Agent 分工的預設流程：新安裝時，Claude Code 擔任大腦，負責前端與影片剪輯；Codex 負責後端與生圖；Gemini 負責文章與文件。某個 Agent 還沒設定時，它的工作交給大腦，計畫預覽會說明原因。每條規則都可以在「派工規則」頁修改或刪除。已經在用 Pyloxa 的話，到那裡按「套用預設流程」，原有的規則會保留。
  • Gemini CLI（實驗性）：在「連線」頁用你自己的付費 Gemini API Key 連上 Gemini CLI，不支援 Google 帳號登入與 AI Pro、Ultra 訂閱。即使你自己的 Gemini 設定選了 Google 帳號登入，Pyloxa 也會讓 Gemini CLI 只用你的 API Key。Gemini 可以執行工作，不能擔任大腦。
  • 同時執行兩個工作：一個計畫最多同時執行兩個互不依賴的工作，每個 CLI 最多同時兩個。會改到同一些檔案的工作會互相等待，計畫卡會說明它在等什麼。
  • 第一個工作的引導：新對話會推薦一個範圍小的第一個工作，並說明流程。資料夾不是 git 專案或還沒有 commit 時，計畫預覽會在你核准前說明。
  • 新版提示與桌面通知：有新版本時 Pyloxa 會提示你。Pyloxa 不在前景時，計畫擬好、工作等你處理、工作完成或失敗、大腦回覆、CLI 額度用盡，都會用 Windows 通知提醒你。兩者都可以在「設定」關閉。
  • 版本警告變少：和已測試版本同系列的修補版（例如 Claude Code 2.1.x）不再顯示「未驗證版本」的警告。
  • PR 說明附上驗證紀錄：建立 pull request 時，可以附上每個 Agent 成果實際經過的檢查：驗收命令、必要檔案、寫入範圍、階段檢查與核准者。沒有執行的檢查不會寫成通過。
  • Skills 盤點：新的「Skills」頁列出各 CLI 讀得到的 Skills，並標示同名但內容不同的。
  • 放在 repo 裡的團隊規則：Pyloxa 會讀取專案裡的 .pyloxa/rules.json 與 .pyloxa/commands.json。你會先看到預覽，規則要你選擇套用才會成為這個專案的規則，命令也照舊要你逐一核准。
  • 使用統計與回報：「設定」頁顯示第一次成功、完成率、備援接手等次數，只在你的電腦計算。「複製診斷資訊」可以把版本與次數複製到問題回報。

隱私

  • Pyloxa 啟動時和每 12 小時會向 GitHub 查詢最新版本。只送出這個查詢，不含任何專案或使用資料。可以在「設定 → 通知與更新」關閉。
  • 「Skills」頁會讀取各 CLI 的 Skills 資料夾（~/.agents/skills、~/.claude/skills、~/.codex/skills、~/.gemini/skills）與開啟中專案的 Skills 資料夾，不讀取這些 CLI 資料夾裡的其他內容，也不做任何修改。
  • 使用統計只在你的電腦計算，不會傳送。診斷資訊不含專案名稱、路徑、指示、程式碼、帳號或金鑰，只有你自己貼到其他地方時才會離開你的電腦。

第一次使用更容易上手，也可以改用自己的 API Key，不一定要訂閱。

新功能

  • 入門引導：沒有任何 Agent CLI 可以使用時，首頁與對話中會說明要安裝什麼，提供可以複製到終端機的官方登入指令（claude auth login 或 codex login），回到 Pyloxa 時自動重新偵測。

Pyloxa Windows 版的第一個免費版本。

功能

  • 一段對話：告訴大腦（Claude Code 或 Codex）你想做什麼。它會先讀過專案，不清楚時先發問，再直接回答或提出分成階段與工作的計畫。
  • 派工規則：由你的規則決定每個工作交給哪個 Agent。每個工作都會標出命中的規則、派工理由與備援；規則頁可以在不呼叫 Agent 的情況下模擬派工。
  • 隔離的工作環境：每個會寫入的工作都在自己的 git worktree 執行。Pyloxa 不會對你的工作目錄執行 stash、reset 或 checkout。
  • 驗證命令：核准 npm run test 這類命令、先試跑，再讓工作執行。檢查全部通過、而且不需要審查的工作會自動接受；沒通過的工作會自動修正一次。
  • 階段 Gate：每個階段結束時，在整合後的成果上執行 Gate 命令。計畫會自動往下走，或等你核准；Gate 沒通過時會自動新增一個修正工作。
  • 額度用盡時：CLI 回報用量上限時，Pyloxa 會把那個連線標為受限、顯示重設時間，並停止派工給它。你可以確認由備援 Agent 從前一個 Agent 的成果接著做，或等額度恢復後自動重試。限流與網路錯誤會自動重試一次。
  • 用量：每個工作與整個計畫的 token 用量。
  • 重啟核對：如果 Pyloxa 在工作進行中結束，下次啟動時會停止殘留的 CLI 程序、保留已完成的部分，並請你核對。
  • 工作區：瀏覽與搜尋檔案、編輯 Markdown 並即時預覽、查看差異、提交、分支、推送與拉取，並透過 gh 開 pull request。
  • 語言與主題：English、繁體中文、简体中文，以及淺色、深色與多種色彩主題。
