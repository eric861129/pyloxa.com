0.1.11

發布於 2026-11-17

這次更新可以存下自己的工作流程、用一句話建立流程，也可以先拿範例專案試駕，再用在自己的專案上。每個完成的計畫都多了驗證報告卡，設定可以備份帶到另一台電腦，選單也多了說明文件。

新功能

  • 先用範例專案試駕。 設定精靈的最後一步，以及還沒有任何專案時的歡迎頁，都有「開始試駕」。Pyloxa 會建立一個藏了四捨五入 bug 的小範例 repo 和事先寫好的計畫，你核准之前什麼都不會執行。有兩個不同的 CLI 時，一個修 bug、另一家測試修好了沒（Pro 自動；免費版由你按「交給另一個 Agent 測試」）；只有一個時，由 Pyloxa 自己執行規格裡的測試。Agent 只能改 src/ 裡的檔案，所以結果通過就代表 bug 真的修好了。開始前會顯示誰做、誰測，以及估計的 Agent 回合數、tokens 與時間。試駕需要 git 與 Node.js，和其他工作一樣用你自己的訂閱或 API Key。
  • 每個完成的計畫都有驗證報告卡。 計畫完成後，下方的「驗證報告卡」列出檢查了什麼：每個工作由誰做、有沒有交叉測試、Pyloxa 自己執行的命令與結果，可以複製成 Markdown。PR 說明裡的驗證紀錄也換成同一張報告卡。最後一行的「Verified with Pyloxa」要你打開才加，而且只有每個成果都通過 Pyloxa 執行的命令、Gate 也都通過時才會這樣寫。
  • 我的流程（Pro）。 在「工作流程」頁按「存成我的流程」，把目前的派工模式、大腦驗收、交叉測試、worktree、階段與分工存成一個有名字的流程，最多 20 個。每個專案可以使用不同的流程，你為專案另外設的規則仍然優先。每個流程保留最近 10 個版本，可以比較任兩版或還原到某一版。沒有 Pro 時專案照全域設定，存好的流程會保留。
  • 用一句話建立流程（Pro）。 在「工作流程」頁按「用一句話建立」，寫下你想要的做法，例如「先寫規格，我核准後再開發；後端交給 Codex；全部都要大腦驗收」。大腦擬好一個流程，並列出做不到的地方。套用到全域設定或存成我的流程之前，會先列出哪些設定會改變。
  • 設定帶著走。 「設定 → 備份與搬移」把 Profile、全域規則、大腦與派工偏好、常用指令範本、全域共用記憶、Skills 庫、外觀與我的流程匯出成一個檔案，在另一台電腦匯入時會先預覽每一項變更。API Key、登入資料與這台電腦的路徑一律不匯出。匯入前會先備份這台的設定，「還原備份」可以回到最近 5 份中的任一份。匯出與匯入免費；檔案裡的 Pro 設定照存，沒有 Pro 時暫停。
  • 派工包可以帶我的流程（Pro）。 派工包可以附上你的流程，匯入時可以順便讓這個專案使用。舊派工包的「流程與慣例」改稱「慣例」。0.1.10 做的派工包照常能匯入。
  • 計畫卡上的階段進度。 核准有兩個以上階段的計畫後，計畫上方會顯示每個階段的狀態與目前在第幾段，點一段就捲到那個階段。
  • 說明文件。 「說明」選單與標題列的 Pyloxa 選單可以開啟 pyloxa.com/help/ 的「說明文件」（英文或繁體中文）。

調整

  • 設定精靈與計畫卡的文字跟上 Pyloxa 現在的做法。歡迎頁不再說 Pyloxa 沒有伺服器：你的程式碼與 Agent 的回覆不會經過 Pyloxa 的伺服器，匿名使用統計預設關閉、你開啟才會傳送。精靈改指向「工作流程」頁，不再是舊的「派工規則」頁。Pro 的計畫卡不再寫「最多同時兩個工作」：同時進行的數量只受各條連線的上限限制。
  • 大腦擬不出流程時，Pyloxa 會說明原因與下一步。
  • 免費版裡，大腦擬好的流程不會套用自動模式。

隱私

  • 沒有新的網路請求。「說明文件」是用瀏覽器開啟 pyloxa.com。
  • 試駕的範例 repo 留在你電腦上 Pyloxa 資料夾的 test-drive 裡。

升級

直接執行新的安裝檔覆蓋舊版即可。存在 %APPDATA%\Pyloxa 的執行紀錄、專案、設定、共用記憶與保存的 API Key 都會保留。資料庫維持第 21 版，所以可以用同一份資料回到 0.1.10；0.1.10 看不到我的流程，也不能匯入含有流程的派工包。

已知限制

  • 只支援 Windows 10 與 11（64 位元）。
  • 安裝檔沒有程式碼簽章，SmartScreen 可能跳出警告；請按「其他資訊」，再按「仍要執行」。
  • Pyloxa 本身不會自動更新。有新版本時 Pyloxa 會提示你。
  • Codex 透過 codex exec 在它的沙箱內執行。在 Windows 上，這個沙箱通常無法建置專案或安裝套件，所以 Codex 的成果以你的驗證命令驗收。
  • Agent 寫的測試程式，在驗證命令執行它時仍在沙箱外執行（環境裡沒有你的金鑰）。新增或修改測試的工作，請看過變更再接受。
  • Gemini CLI 是實驗性支援：不能擔任大腦或交叉測試的測試者，在無人值守模式下也不能執行命令。
  • Agent Teams 是實驗功能。
  • 說明文件目前只有英文與繁體中文。
  • 已測試 Claude Code 2.1.318、Codex CLI 0.166.0，以及 Gemini CLI 0.66.0 與 0.67.0。

0.1.10

發布於 2026-11-16

這次更新開放 Pro 預覽：登入就能免費使用所有 Pro 功能，直到 Pro 開賣。免費版照舊不需要帳號。這一版也重新整理了導覽與設定，介面多了六種語言，並加入選擇加入的匿名使用統計。

Pro 預覽

  • 登入就能免費使用 Pro。 在「設定 → 一般設定」的授權區或任何 Pro 鎖頭按「登入」，在瀏覽器以 Google、GitHub 或寄到 email 的驗證碼登入。預覽期間側欄會顯示「Pro 預覽」。
  • 預覽在 Pro 開賣時結束。 我們會至少提前 30 天在 App 與 email 通知。結束後你還有 14 天的 Pro，並在 App 與帳號頁看到早鳥折扣；之後 App 回到免費版，資料與設定都保留。
  • Pro 包含： 多個專案同時進行，等你處理的事集中在任務中心；在你設定的範圍內自動決定（自動模式）；額度用完時自動備援；自動交叉測試；大腦備援；Agent Teams（實驗）；專案優先序、每條連線的配額與排定時間的計畫；用量儀表板與報告；通知到 Telegram、Discord 或 webhook；同步到各 CLI、依專案或 Profile 指派的 Skills 庫；派工包。
  • 每個帳號 2 台電腦。 在第三台登入時會請你移除一台。帳號頁 account.pyloxa.com/account 列出你的電腦，可以改名、移除、下載你的資料或刪除帳號。
  • Pyloxa 的通知。 登入之後，每天的授權更新可能帶著我們的簡短通知（例如預覽的異動），顯示在視窗上方的橫幅。通知裡的連結只會開 pyloxa.com 或 Pyloxa 在 GitHub 的發布頁。你按掉了哪些通知只記在你的電腦。
  • 贈送的 Pro 在設定、側欄與到期提示裡會標示為贈送。
  • 離線也能用一陣子。 Pyloxa 大約每天更新一次授權。連不到授權服務時，Pro 還能用 14 天，第 3 天起側欄會顯示剩下幾天。

調整

  • 導覽分成兩層。 側欄只放工作：新對話、任務中心、執行紀錄與對話。Agent、工作流程、命令、Skills、記憶、連線與外觀集中到「設定」。
  • 「派工規則」改名「工作流程」。 一頁看完整個流程的五段：規劃、階段、分工、檢查、交付。派工模式、預設路由、計畫的工作方式、Agent Teams、大腦驗收、交叉測試與額度用盡自動備援，都從「Agent 與大腦」搬到這裡；「Agent 與大腦」只留大腦與 Profile。長說明收進說明氣泡。
  • 計畫卡先看成果。 展開工作時，成果與接受按鈕在派工指示前面，可以切換精簡與詳細。
  • 頁面更一致。 設定類的頁面共用頁首與寬度，分頁的樣子統一，提示改用樣式化的氣泡，說明文字變大，載入中與沒有資料時有對應的畫面。
  • 可以選 Enter 或 Ctrl+Enter 送出；新對話的輸入框置中。
  • 檢視面板不再重複按鈕，並記住分頁與寬度。

新功能

  • 分工表。 在「工作流程」頁用一張表選每一種工作由哪個 Agent 做，不必一條一條寫簡單規則。只對一個專案或一個階段的規則照舊在規則清單，而且優先；不分階段的規則會搶走依階段的規則時，Pyloxa 會提示你。
  • 內建的工作流程範本：均衡（預設）、快速修改、嚴謹審查、平均分攤額度。套用前會列出會改變的地方，「還原上一版」可以回到套用前的設定。流程圖、分工表與範本都免費；範本裡屬於 Pro 的設定在免費版不套用，範本上會寫明。
  • 介面多了六種語言：日文、韓文、西班牙文、葡萄牙文（巴西）、德文與法文，加上原本的三種共九種，和官網一樣。Pyloxa 依系統語言自動挑選，可以在「設定 → 一般設定」切換。應用程式選單、系統匣、通知與預設規則的名稱也都翻譯了，大腦也可以用葡萄牙文（巴西）回覆。新的翻譯由 AI 完成，還沒有母語者審閱；哪裡讀起來不對，請告訴我們。
  • 側欄照你的習慣排。 可以拖曳調寬或收成圖示列，把常用的設定頁釘到側欄，「工作」區的項目可以調整順序與隱藏。
  • 更快找到對話。 對話清單依時間分組，可以搜尋、釘選、封存，也可以按右鍵操作。
  • 每個專案可以有自己的顏色。
  • 常用指令範本。 在輸入框打「/」選用存好的指令，用 {{…}} 標出每次要換的地方。免費版可以存 5 個範本，Pro 不限。
  • 自訂快捷鍵：在「設定 → 快捷鍵」。應用程式選單跟著換；和已經在用的快捷鍵衝突時會先問你。
  • 任務中心的版面：區塊可以調整順序與顯示。
  • 版面與顯示的客製化全部免費。

隱私

  • 新的網路請求，只在你登入之後。 登入時用瀏覽器開啟 account.pyloxa.com；之後 Pyloxa 大約每天更新一次授權，只送裝置 ID、裝置憑證與 Pyloxa、Windows 的版本。免費版不會連到授權服務。Pyloxa 的通知跟著同一次每天的更新送來，不會另外連線。

  • 通知（Pro）從你的電腦直接送出，到你設定的 Telegram bot、Discord webhook 或 HTTPS webhook，內容是專案名稱、事件與計畫或工作的標題。

0.1.9

發布於 2026-11-16

這次更新包含更多安全性修正，讓 Agent 可以搜尋與提議共用記憶，並調整 Claude Code 訂閱同時執行的工作數。請從 0.1.8 以前的版本更新。

安全性修正

這些修正來自和 0.1.7、0.1.8 相同的安全審查，目前沒有收到任何一項被利用的回報。

  • Agent 改了命令的執行方式時，驗證命令會等你。 工作改了 package.json 的 script、Makefile 這類建置檔、.npmrc 或命令直接點名的檔案，或是改到寫入範圍以外的檔案時，Pyloxa 不會自己在沙箱外執行驗證命令，工作會說明原因。你看過變更後，按「看過了，執行驗收命令」；就算通過，也要由你接受這個工作。
  • 改到會影響 Agent 與自動化的檔案，一律由你決定。 工作改了 .claude、.github、.husky、CLAUDE.md 這類檔案時，不會自動接受，也不會交給大腦驗收，合併前的對話框會再列出這些檔案。
  • 信任專案的 Agent 設定，涵蓋的範圍更大。 信任確認現在也涵蓋設定檔指向的腳本、hooks 資料夾、放寬權限的 skills、agents 與 commands、Codex 的 hooks，以及 Gemini CLI 的政策與擴充。信任只對一個專案有效：同一個專案的 worktree 算同一個專案，別的 repo 會重新詢問。
  • **Gemini CLI 不再讀專案的 .env。** 專案裡的 .env 可能讓 Gemini 的請求連同你的 API Key 被送到別的伺服器。
  • 計畫不能自己放寬限制。 計畫不經你核准就開始時（固定模式），Pyloxa 會自己檢查兩項上限，不照單全收大腦的計畫：只有實作與測試階段可以不經你核准，每個工作的寫入範圍要寫明資料夾或檔名，不能涵蓋整個專案。不符合時，計畫會等你核准並說明原因。
  • 自動接受的記憶有自己的標示。 Agent 看到的不再寫成由你核准。

調整

  • 計畫中，每個 Claude Code 訂閱同時只跑 1 個工作。 訂閱的額度以一般個人使用為前提，所以在計畫裡，Claude Code 的訂閱連線現在同時只跑 1 個工作；以 API Key 連線的 Claude Code、Codex CLI 與 Gemini CLI 仍是同時 2 個。計畫卡的等待原因會說明。你直接派的單一工作不受這個限制，但會計入。
  • Pyloxa 不再向 Codex 查詢剩餘額度。 Pyloxa 不再啟動 codex app-server。Codex 訂閱在額度一覽改為和 API Key 一樣，只顯示今天的 token。Codex 額度用完時，Pyloxa 仍會標示為受限。
  • 免費版同一時間只有一個專案有工作在跑。 另一個專案還有工作在跑時，你核准的計畫會等待，那邊的工作完成後自動開始。要換成先做這個專案，在計畫卡按「改成先做這個專案」；已經在跑的工作會先做完。
  • 交叉測試與大腦驗收也佔連線名額。 連線忙碌時會排隊等候，不會疊在其他工作上同時跑。
  • 大腦不驗收自己做的工作。 工作是大腦自己做的時候（例如交給大腦的文件工作），大腦驗收會記成沒有完成，工作等你確認，不會自動接受。
  • 輸入框不再用紅色底線標示英文拼字錯誤。 原因請見「隱私」。

新功能

  • Agent 可以使用共用記憶。 Claude Code、Codex CLI 與 Gemini CLI 工作時，可以搜尋你核准過的記憶，也可以提議新的記憶，每個工作最多 5 則。
  • 大腦也可以提議。 你說「以後都用 pnpm」這類的話時，大腦可以提議記下來。大腦驗收時也可以提議它發現的慣例或陷阱。
  • 記什麼由你決定。 提議會出現在「記憶」頁的「待確認」，側欄有數量提示，對話裡也會出現「大腦想記住 N 件事」。每一則都可以接受、修改後接受或捨棄。你接受之前，任何 Agent 都看不到這些提議。每個專案可以設定自動接受 Agent 提議的事實與踩過的坑；規則、偏好、決策與大腦的提議一律等你確認。

  • 連線問題說得更清楚：側欄、Agent 設定與對話中，會顯示真正擋住派工的問題，例如「未登入」，而不是「版本未驗證」。
  • 重新偵測找得到剛安裝的 CLI：重新偵測時會重新讀取 PATH，安裝 CLI 之後不必重開 Pyloxa。
  • 大腦不能用時：輸入框上方會說明原因，並提供處理方式的連結；送不出去的訊息會留下原因。
