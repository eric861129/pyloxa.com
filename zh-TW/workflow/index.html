工作流程

從需求到合併，每一步都照你的設定

Pyloxa 的「工作流程」頁把整個流程攤開成五段：誰來規劃、分成哪些階段、誰做哪一種工作、怎麼檢查、怎麼交付。大腦只負責提計畫，不能改動這些設定；Agent 說做完了也不算數，要你的命令跑過才算。

1. 規劃：誰當大腦、要放手多少

選一個 Agent 當大腦。它先讀過專案，再把需求拆成階段與工作；派工模式決定計畫要不要等你核准。

  • 建議後詢問：大腦提出計畫與派工，你看過、可以改派或修改指示，核准後才開始。
  • 僅依設定執行：每個工作都對得上規則時直接開始；有工作對不上規則就停下來問你。
  • 授權範圍內自動Pro：大腦在你允許的 Agent 中選擇，核准與執行都不必等你，只有人工 Gate 會停。
  • 大腦不能用時，Pro 可以改由備援大腦規劃；大腦一律不驗收自己做的工作。

2. 階段：每段結束先檢查，再往下走

大腦依需求排出階段，例如規格、開發、測試。核准計畫前，你可以在計畫卡上改派某個工作、修改它的指示、決定每個階段做完要不要等你，或請大腦重擬。

  • 照我規定的階段：也可以自己定階段，最多 5 段。每段交給誰、做完要不要等你核准、需求用不到時能不能省略，都由你決定；大腦排計畫時只能用這些階段。免費版也能用。
  • 核准後，計畫卡上方的進度條顯示每一段的狀態與目前在第幾段，點一段就捲到那裡。
  • 每個階段結束時，Pyloxa 在整合後的版本上跑 Gate。Gate 沒通過會重跑一次，再不行就開一個修正工作。
  • Gate 可以通過後自動往下走，也可以停下來等你核准。
  • 下一個階段自動拿到上一段的交接包：成果、通過的檢查和要注意的事。
  • Agent Teams（實驗）Pro：執行中的 Agent 可以看整隊的工作、回報進度，缺少資訊時停下來問你。

3. 分工：一張表決定誰做哪一種工作

分工表的每一列是一種工作，每一欄是一個 Agent Profile。點格子可以設為主要、加為備援、不交給它，或打開進階設定。

  • 決定順序：你在計畫卡上手動指定的、專案規則、全域規則，最後是預設路由；同一層由第一條完全符合的規則決定。
  • 只對一個專案或一個階段的規則寫在「規則清單（進階）」，比分工表優先。分工表的列由哪一條規則決定，表上會寫明。
  • 沒有規則命中時交給預設路由，或停下來問你，由你設定。

4. 檢查：Agent 說做完了不算數

Pyloxa 會建議驗證命令，例如 npm run test。每一條都要你核准，可以先在暫時的 worktree 試跑；大腦只能用你核准過的命令。

  • 工作完成後，Pyloxa 在它自己的 worktree 跑驗收命令、核對必要檔案與寫入範圍。至少有一項客觀檢查、全部通過、而且不需要人看的工作才會自動接受。
  • 沒通過時，同一個 Agent 自動修正一次；每個工作最多自動執行 3 次。
  • 交叉測試：完成的工作交給另一個 Agent 補測試，Pyloxa 在成果上重跑你的命令。測試者只能改測試檔，補上的測試原本的 Agent 改不掉。免費版按「交給另一個 Agent 測試」，Pro 依設定自動進行。
  • 大腦驗收：大腦以唯讀方式檢查完成的工作，結論標示為 AI 判斷；要求你親自確認的工作，仍然等你決定。
  • 想先看一次完整的檢查流程，可以在設定精靈的最後一步「開始試駕」：Pyloxa 建立一個藏了 bug 的範例專案，不會碰到你的專案。

5. 交付：合併與推送由你決定

每個工作在自己的 git worktree 與分支完成，接受後合併到這次計畫的整合分支。合併到你的分支、推送和開 PR，都等你按下；有衝突時 Pyloxa 不會自動解決。

  • 改到 .github、.claude、.codex、CLAUDE.md、AGENTS.md、.mcp.json 或定義驗證命令的檔案時，一律不自動接受，也不交給大腦驗收，合併前會再列出一次。
  • 開 PR 時可以附上驗證報告卡：每個階段一張表，寫明誰做的、誰交叉測試、Pyloxa 跑了哪些命令、成果怎麼被接受。計畫完成後，在計畫卡下方也能打開它、複製 Markdown。
  • 報告卡最後一行預設不加。打開後，只有每個成果都通過 Pyloxa 執行的命令、每個 Gate 也都通過時，才會寫「Verified with Pyloxa」，否則寫「Verification record by Pyloxa」。
  • 需要時可以讓整個計畫共用一個 worktree，工作依序執行，後面的工作看得到前面接受的改動。
  • Pyloxa 不會對你的工作目錄執行 stash、reset 或 checkout。

從範本開始，不滿意就還原

套用範本前，Pyloxa 會列出每一項會改變的設定和每種工作的分派；「還原上一版」可以回到套用前。範本裡屬於 Pro 的設定，免費版不套用，差異裡會寫明。

規格先行先寫規格，做完等你核准，再開發與測試；需求用不到測試時可以省略。

我的流程：每個專案各用一個Pro

設定好之後按「存成我的流程」（最多 20 個），再替每個專案選要用哪一個，例如 API 專案先寫規格、小工具直接改。沒有指定的專案照全域設定；你為某個專案另外設的規則仍然優先。

  • 用一句話建立：描述你想要的做法，大腦擬好流程，先列成差異給你看；要套用到全域、存成我的流程，還是修改描述再擬一次，由你選。大腦不能自己編 Agent，做不到的要求會寫在說明裡。
  • 版本紀錄：每次儲存留一個版本，每個流程最多 10 版。可以比較任兩版，或還原到其中一版；還原前的內容也會留一版。
  • 我的流程可以放進派工包分享，也會跟著「設定帶著走」到新電腦；版本紀錄與專案使用哪一個流程不帶。
  • 回到免費版時，我的流程都保留，專案暫時照全域設定，回到 Pro 就恢復。

常見問題

Agent 說做完了，Pyloxa 怎麼判斷算不算完成？

看你核准的驗證命令。工作完成後，Pyloxa 在那個工作的 worktree 執行驗收命令，並核對必要檔案與寫入範圍。至少有一項客觀檢查而且全部通過、又不需要人看的工作，才會自動接受；沒通過就由同一個 Agent 自動修正一次。沒有執行、跳過或失敗的檢查，不會標成通過。

交叉測試的測試者會改到我的程式嗎？

不會。測試者只能寫入測試檔（例如 *.test.*、*.spec.*、test/、tests/、__tests__/），它補上的測試原本的 Agent 改不掉。測試者不能是做這個工作的同一個 Profile，Gemini CLI 也不能當測試者。

Pyloxa 會自動合併或推送嗎？

不會。工作接受後只合併到這次計畫自己的整合分支；合併到你的分支、推送與開 PR 都由你按下，有衝突時也不會自動解決。改到 .github、CLAUDE.md、AGENTS.md 這類影響 Agent 與自動化的檔案時，一律不自動接受。

分幾個階段由誰決定？

預設由大腦依每個需求決定，核准計畫前你可以在計畫卡上改派工作、修改指示、決定每個階段做完要不要等你，或請大腦重擬。也可以在工作流程頁改成「照我規定的階段」：最多 5 段，每段交給誰、要不要等你核准、能不能省略都由你決定，免費版也能用。

工作流程頁要付費嗎？

不用。工作流程頁、分工表、規則清單、範本、自訂階段、驗證命令、Gate、大腦驗收、手動交叉測試與驗證報告卡都在免費版。Pro 加上我的流程、用一句話建立流程、授權範圍內自動、自動交叉測試、多個專案同時執行與 Agent Teams（實驗）。

可以讓不同的專案用不同的流程嗎？

可以，這是 Pro 功能。把目前的設定存成我的流程，再替每個專案選一個；沒有指定的專案照全域設定。每個流程保留最多 10 個版本，可以比較與還原。
