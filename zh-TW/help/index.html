安裝與更新

需要什麼

  • Windows 10 或 11，64 位元。
  • Git for Windows 2.30 以上。
  • 至少一個 Agent CLI：用你自己的訂閱登入的 Claude Code 或 Codex CLI，或是 API Key。Gemini CLI 是實驗性支援，需要你自己的 Gemini API Key。
  • Node.js 22 以上：只有要讓設定精靈幫你安裝 CLI 時才需要。
  • GitHub CLI（gh）：選用，用來開 pull request。

Pyloxa 不收 AI 用量的費用：CLI 用的是你自己的訂閱或 API Key。

下載與安裝

  1. 從最新版本下載 Pyloxa-Setup-<版本>.exe。
  2. 選用：檢查檔案。在 PowerShell 執行 Get-FileHash .\Pyloxa-Setup-<版本>.exe -Algorithm SHA256，和版本說明裡的 SHA-256 比對。
  3. 執行安裝檔。它只安裝給你這個 Windows 使用者（不需要系統管理員權限），會先顯示授權合約，可以選安裝資料夾，並在開始功能表與桌面建立捷徑。

「Windows 已保護您的電腦」

安裝檔目前還沒有程式碼簽章，所以 Microsoft Defender SmartScreen 可能會擋下它，顯示「Windows 已保護您的電腦」與「未知的發行者」。請按「其他資訊」，再按「仍要執行」。想確認檔案是我們發布的那一個，可以先比對 SHA-256（見上方）。如果是防毒軟體擋下安裝檔或 App，請看防毒軟體擋下 Pyloxa 或 CLI。

更新

  • Pyloxa 啟動時與每 12 小時會到 GitHub 檢查新版本，有新版時顯示橫幅，可以選「查看並下載」、「看看改了什麼」或「略過這個版本」。要關掉的話：設定 → 一般設定 → 通知與更新 →「有新版本時提示我」。
  • Pyloxa 目前還不會自己更新。要更新時，下載新的安裝檔，直接裝在舊版上面即可，專案、設定與紀錄都會保留。
  • 同一個檢查也會下載 Pyloxa 已驗證的 CLI 版本清單（見 CLI 版本）；關掉檢查，這份清單也不會再更新。

設定精靈

第一次開啟 Pyloxa 時，設定精靈會帶你走十個步驟。用「下一步」與「上一步」前後切換，也可以按「略過設定精靈」；之後隨時可以在 設定 → 一般設定 →「重新開啟設定精靈」再打開。

  1. 歡迎：先說明 Pyloxa 和自己開好幾個 Session 有什麼不同：大腦把需求拆成工作、依規則交給不同家的 Agent，Pyloxa 自己跑測試，額度用完經你確認後換手，Agent 不碰你的資料夾、合併與推送由你決定。也可以在這裡選介面語言。已經有可以派工的 Agent 時，這一頁就有「開始試駕」。
  2. 環境檢查：git（必要）與 Node.js（選用）。缺少或版本太舊時，複製畫面上的 winget 命令，或開啟官方下載頁，裝好後按「重新檢查」。
  3. 安裝 Agent：每個 CLI 一張卡。「安裝 {name}」會先讓你看到完整的命令，再以 CLI 官方的 npm 套件（npm install -g …）安裝 Pyloxa 已驗證的最新版本。這一步需要 Node.js。如果裝好了卻找不到，請重新啟動 Pyloxa。
  4. 登入與金鑰：每個 CLI 是否「可以派工」。用畫面上的命令在終端機登入（例如 claude auth login 或 codex login），或改用 API Key。詳見連接 Agent。至少一個 Agent 可以派工時，最上面也有「開始試駕」。
  5. 選大腦：負責規劃工作的 Agent。詳見大腦。
  6. 分工：哪一類工作交給哪個 Agent。之後可以在「工作流程」頁修改。
  7. 工作習慣：worktree 的方式、大腦驗收、交叉測試、精簡回覆、派工模式、沒有規則命中時怎麼辦、驗收方式，以及通知與更新。
  8. Skills：各個 CLI 現在看得到的 Skills。詳見 Skills。
  9. 開啟專案：選一個至少有一次 commit 的 git repo，再核准它的驗證命令。
  10. 第一個工作：說明一個工作怎麼跑，也可以選擇先用範例專案試駕。

精靈結束後，視窗裡會留著「入門清單」，直到你關掉它：連上一個 Agent、選好大腦、開啟專案、核准驗證命令、接受第一個成果、看看 Skills、合併成果或開 PR。第一次用到 App 的各個地方時會出現簡短的提示；可以在 設定 → 一般設定 關掉或重新顯示。

連接 Agent

到 設定 → Agent 與工作流程 →「Agent 連線」。每個 CLI 會顯示版本、相容性、登入狀態、計費方式，以及「可以派工」、「無法派工」或「額度受限」。安裝或登入之後按「重新偵測」。

訂閱帳號（Claude Code 與 Codex CLI）

在終端機用 CLI 自己的命令登入：Claude Code 是 claude auth login，Codex CLI 是 codex login。Pyloxa 只用 CLI 自己的狀態命令確認是否登入，並像你一樣啟動 CLI；不會讀取、複製或傳送你的 token 或憑證檔。

API Key

  • 在 CLI 的卡片按「改用 API Key…」，貼上金鑰：Claude Code 用 Anthropic Console 的金鑰，Codex CLI 用 OpenAI Platform 的金鑰，Gemini CLI 用 Google AI Studio 的金鑰。切換計費方式前 Pyloxa 會請你確認。
  • 金鑰以 Windows 本身的安全儲存加密保存，畫面上只顯示最後四碼。「改回訂閱」會回到 CLI 自己的登入。
  • API Key 由服務商依用量計費，Pyloxa 不另外收費。

Gemini CLI（實驗性）

Gemini CLI 只能用你自己的付費 Gemini API Key，不支援 Google 帳號登入與 Google 的訂閱方案。Pyloxa 用一個獨立的設定資料夾執行它。它可以接寫作、文件之類的工作，但不能擔任大腦，也不能測試其他 Agent 的成果。

CLI 版本

Pyloxa 會測試它支援的每個 CLI 版本。連線卡上會顯示三種狀態之一：

  • 已驗證版本：和 Pyloxa 一起測試過。
  • 與已驗證版本同系列：主版號與次版號和測試過的版本相同。
  • 未驗證版本（只能用監督模式）：還是可以執行，但「授權範圍內自動」不會使用它。

CLI 有新版本時，卡片上會顯示「更新到 {version}」（Pyloxa 已驗證的最新版本）、「複製命令」與 CLI 官方的更新說明。CLI 自己更新之後，會有橫幅告訴你現在是哪個版本。

第一個計畫

送出需求

開啟專案，在訊息框描述你想完成的事。在「交給誰」選「交給大腦」讓它規劃，或選「直接交給 {name}」，不經過計畫，直接把一個工作交給一個 Agent。輸入 / 可以插入常用指令；免費版最多存五個，Pro Pro 不限數量。

大腦

大腦是你的其中一個 Agent。它回答問題、把需求拆成階段與工作，也可以驗收成果。在 設定 → Agent 與工作流程 →「Agent 與大腦」選擇，也可以在那裡設定「大腦的模型」與「大腦的思考強度」；這兩項只影響大腦，不影響執行工作的 Agent。大腦不能改你的設定。Gemini CLI 不能擔任大腦。主要大腦不能用時接手的備援大腦是 Pro。

核准計畫

  • 計畫卡列出各階段、各個工作，以及每個工作交給哪個 Agent。可以按「核准並開始」、「請大腦修訂」，或直接回覆大腦。
  • 核准有兩個以上階段的計畫後，計畫卡上方會顯示「階段進度」：每一段的狀態（已通過、進行中、等你核准、需要你處理、已取消、還沒開始）與目前在第幾段，點一段會捲到那個階段。
  • 每個工作在自己的 git worktree 裡進行，不會碰到你正在編輯的資料夾。Pyloxa 不會對你的工作目錄做 stash、reset 或 checkout。也可以把計畫改成「整個計畫共用一個 worktree」，工作會依序進行，看得到前面的改動。
  • 工作完成後會跑驗證（見驗證）。可以按「接受結果」、「重試」、「改派給其他 Agent」或「放棄這份成果」，也可以開啟 Session 看 Agent 做了什麼。
  • 整個計畫完成後，按「合併到目前分支」或「建立分支並開 PR」。你決定之前，什麼都不會合併或推送。

派工規則與派工模式

規則在 設定 → Agent 與工作流程 →「工作流程」。「分工」的分工表決定每一類工作交給哪個 Agent，備援只在 Agent 出問題（例如額度用盡）時才用。「規則模擬」可以看一個工作會被派到哪裡，不會呼叫任何 Agent。「派工模式」決定計畫怎麼開始：

  • 建議後詢問（預設）：大腦提出計畫，你核准。
  • 僅依設定執行：每個工作都有規則命中時直接開始；每個完成的工作仍由你確認。
  • 授權範圍內自動 Pro：大腦在規則允許的 Agent 裡挑選，不用問你就開始，碰到任何上限就暫停。只會用已驗證的 CLI 版本。

同時能跑多少

  • 免費版：一個計畫同時最多兩個工作，同一時間只有一個專案有工作在跑。第二個專案的計畫會排隊（「核准並排隊等待」），也可以選「改成先做這個專案」。
  • Pro：多個專案同時進行，一個計畫裡也沒有數量上限，只受各條連線自己的上限限制。
  • 所有版本：每條 CLI 連線同時最多兩個工作，用訂閱的 Claude Code 一次一個。

驗證、大腦驗收與交叉測試

Agent 說做完了不算數，Pyloxa 會自己檢查每一份成果。

驗證命令與 Gate

  • 在 設定 → Agent 與工作流程 →「驗證命令」核准專案的命令（測試、建置、lint）。每個工作完成後 Pyloxa 會執行它們，並檢查改動的檔案有沒有超出計畫允許的寫入範圍。
  • 只有至少有一項檢查、全部通過、而且不需要人工審查時，成果才會自動接受。檢查失敗時，會請同一個 Agent 修正。每個工作最多自動執行三次，重試、修正與備援接手都算在內。
  • 每個階段結束時有 Gate：在合併後的版本上執行它的命令。沒有 Gate 命令的階段會等你按「核准此階段」。

大腦驗收

在「工作流程」頁的「檢查」，「大腦驗收」可以關閉（預設）、只驗收沒有驗收命令的工作，或驗收所有工作。大腦只讀不改，決定接受、要求修改或問你；它的判斷會標示為 AI 判斷。大腦不會驗收自己做的工作：由備援大腦 Pro 驗收，沒有的話就等你處理。

交叉測試

  • 免費版：在完成的工作上按「交給另一個 Agent 測試」。測試者在自己的 worktree 裡工作，只能新增測試。Pyloxa 會自己重跑命令，以命令的結果為準。測試沒過時，按「交回「{name}」修正」。
  • Pro：依工作類型或由大腦判斷自動交叉測試、每條派工規則指定測試者、在計畫裡逐一選擇要不要測，以及測試失敗時自動交回修正。
  • Gemini CLI 不能擔任測試者。

工作流程

設定 → Agent 與工作流程 →「工作流程」顯示工作經過的五段：規劃、階段、分工、檢查、交付。點任一段會跳到它的設定。

  • 「從範本開始」：均衡（預設）、快速修改、規格先行、嚴謹審查、平均分攤額度。套用前會先列出會改什麼，「還原上一版」可以復原。免費版套用範本時，會略過其中的 Pro 部分（授權範圍內自動、自動交叉測試、自動備援），預覽會標出來。
  • 「計畫的階段」：由大腦依每個需求決定（預設），或「照我規定的階段」：最多五個，每個可以設定名稱、由誰做、給大腦的說明、做完要不要等你核准，以及需求用不到時能不能省略。
  • 「我的流程」Pro：「存成我的流程」把目前的設定存成一個有名字的流程（最多 20 個），再替每個專案選要用哪一個。沒有 Pro 時，專案照全域設定，存好的流程會保留。
  • 「版本紀錄」Pro：我的流程每次儲存、內容有變時留一個版本，每個流程最多 10 個，最舊的先丟。選兩個版本「比較」，或「還原這一版」：內容換成那一版、名稱不變，還原前的內容也會留一版，使用它的專案跟著更新。版本紀錄只留在這台電腦，不會跟著設定檔或派工包走。
  • 「用一句話建立」Pro：用一句話寫出你想要的流程，按「請大腦擬」。大腦只讀不改地看過專案，提出設定、說明與改動清單，通常一兩分鐘。之後可以套用到全域（可以復原）、存成我的流程，或修改描述再擬一次。

Agent Teams Pro

Agent Teams 是實驗功能，讓同一個計畫裡的 Agent 互相溝通：分工、回報進度、提問與傳訊息，由大腦或你擔任 Lead。

  • 在 工作流程 → 階段 →「Agent Teams（實驗）」開啟，預設關閉。核准計畫時，這個設定會固定在那個計畫裡。
  • 開啟後，訊息框會多一個「團隊做法」：由大腦決定、功能小隊（先定介面，前後端同時做）、審查委員會（多角度審查，彙整報告）或假設辯論（分頭調查原因，再修正）。
  • 成員提問時，會在「團隊」面板等你回覆（「回覆並接續」）。預設先由大腦處理成員的問題，每個計畫最多八次。
  • 每位成員與每個計畫的訊息數有上限，成員不能自己再開子 Agent。只有 Claude 訂閱時，工作仍然一次一個。

試駕與驗證報告卡

先用範例專案試駕

在設定精靈的最後一步，或還沒有任何專案時的歡迎畫面，按「開始試駕」。已經登入 Agent 的話，精靈的第 1 步（歡迎）與第 4 步（登入與金鑰）也有這個按鈕。從前面開始試駕時，精靈會以預設值結束：大腦與分工都用預設的，側欄的「入門清單」列出還沒做的事，之後可以在 設定 → 一般設定 重新開啟精靈。Pyloxa 會在它的資料夾裡建立一個藏了一個 bug 的小型範例 repo，並附上寫好的計畫，所以大腦不會用到額度。導覽會帶你走過：核准計畫、Agent 修正、Pyloxa 執行 node --test、有第二個 Agent 時由它交叉測試、接受結果，最後是驗證報告卡。預覽會估算大約會用多少。試駕需要 git 與 Node.js，本身是免費的；其中的自動交叉測試需要 Pro，免費版要自己按下測試。試完可以刪掉範例資料夾。

驗證報告卡

計畫完成後，計畫卡上的「驗證報告卡」整理每一份成果：✅ 通過 Pyloxa 執行的命令、⚠️ 沒有命令驗證、❌ 有檢查沒過、⏳ 還沒完成。每份成果會列出由誰完成、交叉測試的結果與新增的測試、跑了哪些命令，以及怎麼被接受的。可以按「複製 Markdown」，或在開 PR 時選擇把報告卡附在說明最後。

共用記憶

共用記憶是放在你電腦上的一份記憶，每個 Agent 工作時都會拿到它當作背景資料：規則、偏好、決定、事實與踩過的坑。免費版就有。在 設定 → Agent 與工作流程 →「共用記憶」開啟。

  • 可以「新增記憶」、搜尋、「釘選：每次都帶入」、封存或刪除。每則最多 500 字，看起來像祕密的內容會被拒絕。每次派工大約帶入 3,000 字。
  • Agent 與大腦工作時可以提議新的記憶，提議會放在「待確認」等你接受、修改或捨棄；也可以讓某個專案自動接受事實與踩過的坑。在回覆或成果下按「記住」可以自己存一則。
  • 可以從各 CLI 原本的記憶檔匯入，例如 CLAUDE.md、AGENTS.md 與 GEMINI.md。Pyloxa 只讀取這些檔案。
  • 「同步到各 CLI」會先讓你看改動，再把專案規則寫進 AGENTS.md 裡一段有標記的區塊（並從 CLAUDE.md 連過去）。Pyloxa 不會替你 commit。
  • 可以匯出成 Markdown 或 JSON，也可以從檔案匯入。

Skills

設定 → Agent 與工作流程 →「Skills」列出每個 Skill，以及哪些 CLI 看得到它。

  • 免費版：盤點與檢視 Skills、「重新盤點」，並可以加入最多十個要盤點的資料夾。
  • Pro：所有 CLI 共用一個 Skills 庫：「新增 Skill」、「以 Skills 庫為準同步」、「補齊缺少的」、編輯與移除。會被取代的檔案會先備份；放寬權限或會執行程式的 Skill 需要你同意。
  • Pro：「這個專案的 Skills」決定每個專案，或每個 Claude Code、Codex 的 Profile 要用哪些 Skills。
  • Pyloxa 派工給 Gemini CLI 時，Gemini 讀不到你使用者層的 Skills；指派之後 Pro，勾選的 Skills 會在每次執行時帶入。
  • Pro 結束後，Skills 庫與已同步的檔案都會留著，CLI 照樣讀得到；指派會保留，但不會套用。

背景執行

以下都在免費版裡，位於 設定 → 一般設定 →「背景執行」。

  • 「關閉視窗時」：有工作時留在系統匣（預設）、一律留在系統匣，或直接結束。系統匣圖示會顯示正在跑什麼，有事需要你時會出現紅點。
  • 「工作執行中防止電腦自動睡眠」（預設開啟）：只在接上電源時擋住閒置睡眠。闔上筆電或自己選「睡眠」仍會睡眠。
  • 有工作在跑時結束 Pyloxa 會先詢問：「做完再結束」讓執行中的工作先做完，「立即結束」會停止它們，改到一半的內容會保留。
  • 下次開啟 Pyloxa 時，被中斷的工作會列出來，按「全部接續」由同一個 Agent 從保存的進度繼續。

用量與額度

用量表

  • 標題列會顯示每個 Agent 還剩多少額度，例如「Claude Code 剩 62%」。點一下可以看各個視窗（5 小時、7 天）與今天用的 token。
  • 用訂閱的 Claude Code 會顯示真正的額度視窗，在 Pyloxa 執行它時更新。這份額度和 claude.ai 與你的終端機共用。
  • Codex CLI 不會回報訂閱額度，所以只顯示 token。API Key 與 Gemini CLI 依用量計費，沒有額度視窗。畫面上的費用是 CLI 自己的估算，不是帳單。
  • 要隱藏的話：設定 → 外觀 → 版面 →「標題列顯示 Agent 額度」。

Agent 額度用盡時

  • Pyloxa 會把這條連線標成額度用盡，在重設時間之前不再派工給它。不知道重設時間的話，額度恢復後在「Agent 連線」按「額度已恢復」。
  • 在計畫卡上，按「由 {name} 接手」讓備援 Agent 從已經改好的檔案繼續，或按「額度恢復後重試」。等待中的工作會在重設後繼續。
  • 短暫的限流會等一下自動重試；服務或網路錯誤會自動重試一次。
  • Pro：「額度用盡時自動由備援接手」（工作流程 → 分工）不用問你，就把工作交給規則裡的備援，每個工作最多兩次，而且只交給相同計費方式的連線。

排程、任務中心與通知

  • 「任務中心」Pro（側欄）：所有專案裡等你處理的事、各專案的進度、已排程的計畫，以及用量與工時，可以匯出成 Markdown 或 CSV。
  • 計畫卡上的「核准，排程開始…」Pro：在指定時間或下次額度重設後開始。Pyloxa 必須開著（留在系統匣就可以）。
  • 「這個專案的額度調度…」Pro（側欄的專案選單）：專案的優先序，以及每條連線可以用多少額度。
  • 「大腦備援」Pro（Agent 與大腦）：最多三個，在主要大腦額度用盡、登出或一直出錯時接手規劃、回答與驗收。
  • 「傳到手機的通知」Pro（一般設定）：把「等你處理」、「計畫完成」、「Gate 沒通過」與「額度用盡」傳到你自己的 Telegram bot、Discord 頻道或 webhook。通知直接從你的電腦送出，Pyloxa 開著時才會送。Windows 桌面通知是免費的。
  • 「派工包」Pro（工作流程 → 規則清單）：把規則、我的流程、Skills、慣例與建議的命令匯出或匯入成 zip 或資料夾。匯入時逐項預覽，既有的規則與流程不會被覆寫：和你的流程同名而內容不同時，預設保留你的，勾了才取代（原本的留在版本紀錄），也可以勾「讓這個專案使用」。流程以 CLI 名稱表示，匯入時對應到這台電腦的 Profile。舊派工包的「流程與慣例」現在叫「慣例」，會成為專案的共用記憶；0.1.10 做的派工包照常能匯入。免費版也會讀 repo 裡 .pyloxa/ 資料夾的規則。

備份與搬移設定

設定 → 一般設定 →「備份與搬移」，免費版就有。沒有雲端同步，檔案由你自己搬。

  • 「匯出設定…」把你勾選的項目存成一個 .pyloxa-settings 檔：Agent Profile、全域派工規則、派工與大腦的偏好、我的流程、常用指令範本、全域共用記憶、Skills 庫與介面偏好。匯出派工規則、偏好或我的流程時，會一起帶上它們用到的 Profile。
  • 不會包含 API Key、授權、專案設定、專案使用哪一個流程、流程的版本紀錄與這台電腦的路徑。含有祕密的項目會被略過並列出來。
  • 「匯入設定…」會先列出會改什麼；內容不同的項目預設保留這台電腦的版本，勾選了才換掉。套用前會先自動備份目前的設定，「還原備份…」可以還原最近五份之一。
  • 我的流程依名稱比對：內容相同的略過；同名而內容不同的預設保留這台的，勾了才取代，原本的內容留在版本紀錄。最多 20 個，超過的不匯入。沒有 Pro 時照樣存起來，要讓專案使用需要 Pro。
  • 在新電腦上，還是要登入各 CLI 或填 API Key、加入專案資料夾；要用 Pro 的話，登入你的帳號。

Pro 帳號、試用與 Pro 預覽

免費版不需要帳號。試用、Pro 預覽與 Pro 需要登入；帳號只用來授權，看不到你的專案或程式碼。帳號會保存哪些資料，請看隱私權政策。

登入

  • 設定 → 一般設定 →「授權」→「登入」。瀏覽器會開啟 account.pyloxa.com：以 Google 或 GitHub 繼續，或用寄到 email 的 6 位數驗證碼（10 分鐘內有效）。請在 5 分鐘內完成，再回到 Pyloxa。
  • 同一個已驗證的 email 永遠是同一個帳號。

Pro 預覽與試用

  • Pro 預覽：登入就能免費使用完整的 Pro，到 2026 年 12 月 31 日（台灣時間）。參加預覽的人之後還有 14 天的 Pro，到 2027 年 1 月 14 日。
  • 試用：沒有 Pro 預覽時，第一次登入會開始 14 天的 Pro 試用，不需要信用卡。每個帳號、每台電腦都只能試用一次。側欄會顯示還剩幾天。
  • 2026 年 12 月 1 日起，「授權」卡與帳號頁會出現「購買 Pro」。參加預覽的人結帳時會自動套用早鳥價，不用輸入折扣碼。購買適用 Pro 使用條款與退款政策：第一次購買後 30 天內可以不附理由全額退款。

兩台電腦

  • 一個帳號可以在兩台電腦登入。「登出這台電腦」會騰出這台的名額，不會刪除任何資料。
  • 在第三台電腦登入時，登入頁會列出另外兩台，可以移除其中一台。也可以在「帳號頁」重新命名或移除電腦。移除電腦 30 天內最多三次；超過之後請寫信到 support@pyloxa.com。

保持連線

  • Pyloxa 大約每天更新一次授權，只送出裝置 ID、它的憑證，以及 App 與 Windows 的版本。「重新檢查」會立刻更新。
  • 連不到授權服務時，從上次成功更新起算，Pro 還可以用 14 天；離線超過三天 App 會提醒你。超過之後 Pro 會暫停，等更新成功就恢復。
  • 如果公司網路擋了 account.pyloxa.com，請把「授權」卡上顯示的裝置 ID 寄到 support@pyloxa.com。我們可以寄給你啟用碼，貼在「有客服給的啟用碼？」。

試用、預覽或 Pro 結束時

Pyloxa 會回到免費版。執行中的工作會先做完，不會刪除任何資料、檔案或設定。Pro 的設定會暫停，並標示「需要 Pro，已暫停」；回到 Pro 時立即恢復。

資料放在哪裡，以及解除安裝

資料夾裡面有什麼
%APPDATA%\Pyloxa設定、紀錄與資料庫（pyloxa.sqlite3）、加密保存的 API Key 與授權（secrets.json）、Skills 與記憶的備份，以及試駕的範例專案
%LOCALAPPDATA%\Pyloxa\worktreesAgent 工作用的 git worktree
你的 repo名稱是 pyloxa/… 的工作分支，以及你合併進去的內容

Pyloxa 不會把這些資料夾的內容傳給我們。解除安裝前，先在系統匣圖示上結束 Pyloxa（關掉視窗它可能還在背景執行），再到 Windows 的 設定 → 應用程式，像其他 App 一樣解除安裝。解除安裝會保留上面兩個資料夾，重新安裝後可以接著用。要全部移除的話：

  1. 刪除 %APPDATA%\Pyloxa 與 %LOCALAPPDATA%\Pyloxa。
  2. 在用過的每個 repo 執行 git worktree prune，再刪掉不需要的 pyloxa/… 分支。
  3. 用過「同步到各 CLI」的話，從 AGENTS.md 與各 CLI 的記憶檔刪掉 Pyloxa 標記的區塊。CLI 本身與同步過去的 Skills 會留著。
  4. 登入過的話，在帳號頁刪除帳號，或寫信到 support@pyloxa.com 請我們刪除。

疑難排解

Windows 對安裝檔發出警告

請看「Windows 已保護您的電腦」。

防毒軟體擋下 Pyloxa 或 CLI

因為 App 還沒有程式碼簽章，有些防毒軟體會隔離安裝檔、不讓 Pyloxa 啟動，或擋下它啟動的 CLI。可能的樣子：安裝檔不見了、CLI 在終端機能用但 Pyloxa 顯示沒有安裝，或工作失敗並顯示「無法啟動 claude」（或 codex、gemini）。

  • 先用版本說明裡的 SHA-256 確認檔案，再從隔離區還原，或在防毒軟體裡允許它。請允許 Pyloxa 的安裝資料夾，不要直接關掉防護。
  • 每個新版本都是新的檔案，更新之後可能要再允許一次。
  • 接著在「Agent 連線」按「重新偵測」。

CLI 顯示「無法派工」

  • 需要重新登入：在終端機重新登入（claude auth login、codex login），再按「重新偵測」。
  • 找不到 CLI：安裝它；剛裝好的話，重新啟動 Pyloxa。
  • 未驗證版本：仍可以用監督模式執行。要換成已驗證的版本，在它的卡片按「更新到 {version}」。
  • 設定 → 一般設定 → 使用統計與回報 →「複製診斷資訊」會複製各版本與連線狀態，回報問題時很有用。

工作因為錯誤停下來

  • 訂閱額度用盡：等額度重設，或讓另一個 Agent 接手。詳見 Agent 額度用盡時。
  • 暫時限流或服務或網路錯誤：Pyloxa 會自己重試一次；還是不行的話，確認網路後按「重試」。
  • 無法解析 CLI 的輸出：請附上這次執行的紀錄回報問題。
  • 自動執行三次後檢查仍然沒過：開啟 Session 看發生什麼事，再重試、改派，或自己修正。

登入或授權的問題

  • 「連不到 Pyloxa 授權服務」：確認網路；公司網路可能擋了 account.pyloxa.com。詳見保持連線。
  • 「這個授權已經在 2 台電腦登入」：在登入頁或帳號頁移除一台。
  • 「登入逾時」：重新按「登入」，在 5 分鐘內完成。

資料夾無法開成專案

Pyloxa 需要一個至少有一次 commit 的 git repo。先執行 git init 並做第一次 commit，再重新開啟資料夾。

回報問題

  • 在 App 裡：設定 → 一般設定 → 使用統計與回報 →「回報問題或建議」會開啟我們的 GitHub 回報表單：「問題回報」或「功能建議」。回報問題時，貼上「複製診斷資訊」複製的內容。
  • Issue 是公開的。不要貼 token、API Key 或不能公開的程式碼，也請檢查截圖裡有沒有專案名稱、檔案內容或帳號資料。
  • 帳號、授權或不方便公開的問題，請寫信到 support@pyloxa.com。
  • 資安漏洞：請透過 GitHub 的安全性通報私下回報，不要開公開的 issue。
