一份記憶，三個 CLI 都讀

在「共用記憶」按「記住」，或從對話裡記下一件事。每一則記憶有範圍（全域或這個專案）與種類：規則、偏好、決策、事實、踩過的坑。

  • 派工、大腦規劃、大腦驗收與交叉測試時，Pyloxa 把相關的記憶放進提示，標明是背景資料，不是指令。
  • 順序是：釘選的記憶、規則與偏好（專案的在全域之前），再加上最相關的事實、決策與踩過的坑，最多 12 則。
  • 每次帶入的總長度預設 3,000 字，可以改成 1,000 或 6,000；每一則最多 500 字。
  • 執行紀錄會寫明這次帶入了幾則記憶。

Agent 提議，你核准

Agent 工作時可以透過 Pyloxa 提供的工具搜尋記憶、提議新的記憶。每一則提議都先放進「待確認」，你接受之前，任何 Agent 都看不到。

  • 每個工作最多提議 5 則，大腦每回合最多採用 3 則，不會讓記憶一下子膨脹。
  • 看起來像金鑰、token 的文字會被拒絕，不會存進記憶。
  • 想省事的話，可以讓某個專案「自動接受 Agent 提議的事實與踩過的坑」，預設關閉；規則與偏好一律要你核准。
  • 記憶工具只在本機的 127.0.0.1 提供，每次執行有自己的 token。

在終端機直接用 CLI，也讀得到

不透過 Pyloxa、直接在終端機開 CLI 時，記憶也能跟著走。「同步到各 CLI」把專案的記憶寫成 AGENTS.md 裡的 Pyloxa 區塊，並在 CLAUDE.md 加上 @AGENTS.md，Gemini CLI 也可以設定讀這個檔案。

  • 寫入前先給你看差異，按下才寫；Pyloxa 不會替你提交。
  • 「也寫進各 CLI 的使用者層記憶」預設關閉。打開後，Pyloxa 第一次寫入前先備份 ~/.claude/CLAUDE.md、~/.codex/AGENTS.md、~/.gemini/GEMINI.md，關掉時把自己的區塊拿掉。
  • 反過來也可以：從 CLI 原本的記憶檔匯入，只讀固定的檔案，例如專案的 CLAUDE.md、.claude/rules/*.md、AGENTS.md、GEMINI.md，以及 Codex 的 Memories。不讀憑證、設定或對話紀錄。
  • 記憶可以匯出成 Markdown 或 JSON，也能從檔案匯入。

Skills：先看清楚每個 CLI 讀得到什麼

「Skills 盤點」列出每個 CLI 實際讀得到的 Skills，用一張 Skill × Agent 的表看出哪裡缺、哪裡重複。這部分免費。

  • Skills 庫Pro：把 Skills 集中放在 ~/.agents/skills，新增、修改、刪除後同步到各 CLI。
  • 指派Pro：依專案或 Profile 決定哪些 Skills 要帶給哪個 Agent。
  • 派工包Pro：把規則、驗證命令建議、慣例和 Skills 打包成一個檔案分享，匯入時逐項預覽，既有的規則不會被覆寫。
  • Gemini CLI 執行時看不到使用者層的 Skills，只會拿到透過 Pro 指派給它的 Skills。

常見問題

共用記憶存在哪裡？會傳到雲端嗎？

存在你的電腦，不會傳給我們，也不在匿名使用統計裡。只有派工時，相關的記憶會跟著提示送到那個 CLI 原本會送去的地方。

Agent 會不會自己把錯的東西寫進記憶？

不會直接生效。Agent 的提議都先放進「待確認」，你接受之前任何 Agent 都看不到。只有你為某個專案打開「自動接受 Agent 提議的事實與踩過的坑」時，事實與坑才會自動接受；規則與偏好一律要你核准。

已經有 CLAUDE.md 或 AGENTS.md，還需要這個嗎？

可以直接匯入。Pyloxa 從固定的記憶檔讀進來，之後由同一份記憶帶給三個 CLI；需要在終端機直接用 CLI 時，再用「同步到各 CLI」寫回 AGENTS.md 的 Pyloxa 區塊，寫入前先看差異。

Skills 盤點要付費嗎？

不用。盤點每個 CLI 讀得到的 Skills 是免費功能；Skills 庫、依專案或 Profile 指派與派工包屬於 Pro。
