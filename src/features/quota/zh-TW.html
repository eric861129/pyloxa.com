額度用完時，你決定誰接手

CLI 回報額度用盡時，Pyloxa 把那條連線標為受限，在重設時間到之前（或你按「額度已恢復」之前）不再派工給它。免費版每次接手都由你確認。

  • 由另一個 CLI 接手：依你在規則裡設定的備援，下一個 Agent 從前一個 Agent 已經改好的檔案接著做。
  • 額度恢復後重試：知道重設時間時自動開始；不知道時，等你按「額度已恢復」。
  • 每個工作最多自動執行 3 次、換手 2 次，不會交回已經失敗過的 Agent。
  • 短暫的速率限制（5 分鐘以內）重試一次；網路錯誤 30 秒後重試一次。
  • 自動接手只會換到同一種計費方式的連線：用訂閱的工作不會自動改用 API Key 計費。

Pro：自動接手，額度照你的安排用

不想每次都按確認的話，Pro 可以照規則裡的備援鏈自動接手，也能決定哪個專案先用額度、什麼時候開始。

  • 額度用盡時自動由備援接手：預設關閉，計畫核准時就決定好；額度用盡或工作在等受限的連線時觸發，上限一樣是每個工作換手 2 次。
  • 優先序與每條連線的配額：決定專案的先後，替每條連線設一個估計的配額。配額是估計值，不是供應商的上限，也不能當計費依據。
  • 排定開始時間：整個計畫排到下次額度重設後，或 30 天內指定的時間。晚了 30 分鐘以內照常開始，更晚就等你決定；開始前 24 小時內接著電源時不讓電腦睡眠。
  • 大腦備援：最多 3 個備援大腦。大腦的服務出錯時重試一次，再由下一個接手，10 分鐘後才換回來。
  • 用量與工時：跨專案的用量儀表板，可以匯出成 Markdown 或 CSV。

常見問題

Pyloxa 怎麼知道 Claude Code 還剩多少額度？

Claude Code 執行時會自己回報額度事件，Pyloxa 讀這些事件，不另外查詢、不讀憑證。所以標題列在執行之後才會更新，顯示 5 小時與 7 天兩個額度中比較緊的那一個。

為什麼 Codex 只顯示 tokens？

Codex 執行時不回報訂閱還剩多少，而 Pyloxa 不用其他方式查詢 Codex 的額度。所以 Codex 只顯示今天用了多少 tokens；被限制時，標題列會標示出來。

換另一個 CLI 接手，會從頭做起嗎？

不會。接手的 Agent 從前一個 Agent 已經改好的檔案接著做。每個工作最多換手 2 次，也不會交回已經失敗過的 Agent。

額度用完時，Pyloxa 會改用 API Key 付費嗎？

不會自動改用。自動接手只會換到同一種計費方式的連線，用訂閱的工作不會自動改用 API Key；要不要換到 API Key 的連線，由你決定。Pyloxa 也不轉售或代理任何 AI 服務，用量都算在你自己的訂閱或 API Key。
