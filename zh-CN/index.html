不只是多开几个 Agent

能同时开好几个 Agent 的工具已经不少。Pyloxa 处理的是 Agent 之间的事：谁做哪一部分、做完怎么确认、卡住时谁来接手。

下面是同一个需求的三种做法：自己在几个 CLI 之间切换、用终端复用工具把多个 Agent 的终端并排，以及交给 Pyloxa。

分工 自己判断每件事适合哪个工具，再把需求复制过去。 你决定每个终端里的 Agent 做什么；有些工具也允许 Agent 自己启动其他 Agent。 大脑把需求拆成阶段和任务，按你的规则派给 Agent；每个任务都写明命中了哪条规则。
交接 前一个 Agent 做完后，你把 API 格式和文件路径贴给下一个。 Agent 之间可以互发消息，交接什么由 Agent 自己决定。 下一个阶段自动拿到交接包：成果、已通过的检查和需要注意的地方。

你的仓库 Agent 直接改你的工作目录。 取决于你在终端里怎么打开：通常就在你的工作目录。 每个任务都在自己的 git worktree 中进行，完成后核对改动是否都在允许的写入范围内；合并和推送由你决定。

按你的方式分工

用哪个模型、哪类任务交给谁、做到哪一步要先问你，都由你设置。大脑只负责提出计划，不能改动这些设置。

每个 Agent 都是你设置的 Profile

Profile 决定用哪个 CLI、哪个模型、多少推理，以及每个任务附带的角色提示词。同一个 CLI 可以建多个，例如“Claude 前端”和“Claude 文档”。

  • 模型列表直接取自你安装的 CLI；推理参数显示各家原生的值（Claude Code 的 --effort、Codex 的 model_reasoning_effort），不强行换算成同一套刻度。
  • 任何一个 Profile 都可以当大脑，负责读项目和拆计划；大脑和执行任务的 Agent 可以用不同的模型。
  • Profile 只保存设置，不保存任何凭据。

谁来做，由你的规则决定

规则按“阶段类型”加“任务类型”匹配，例如“开发阶段的后端任务交给 Codex 后端”。每条规则有一个主 Profile 和备用顺序，可以应用到所有项目，也可以只用于当前项目。

  • 规则从上往下匹配，第一条完全匹配的生效；一条规则把另一条规则遮住时会提醒你。
  • 规则模拟不调用 Agent、不消耗额度：选一类任务，就能看到会交给谁、为什么。
  • 没有规则匹配时，可以设为在计划预览中问你，或者直接停下。Pyloxa 不会随便挑一个 Agent。

每个阶段做完，用你的命令验收

大脑按需求排出阶段，例如规格、接口契约、开发、测试。批准前，你可以改派某个任务、修改它的说明，或让大脑重新规划。

  • 验证命令需要你批准，例如 npm run test，可以先在临时 worktree 中试运行。大脑只能使用你批准过的命令。
  • 每个任务完成后，在它自己的 worktree 中验收；每个阶段结束时，在集成后的版本上再跑一次 Gate。
  • Gate 通过后可以自动进入下一步，也可以停下来等你批准。
  • 完成的任务可以交给另一个 Agent 测试，例如 Codex 开发、Claude Code 补测试。测试方只能修改测试文件，Pyloxa 会在结果上重新运行你的命令。
  • 大脑可以验收完成的任务，使用它自己的模型和思考强度。结论会标注为 AI 验收；要求你亲自确认的任务，仍然等你决定。

放手多少，由你决定

派工模式决定 Pyloxa 什么时候先问你。无论哪种模式，推送和部署都不会自动进行。

  • 大脑和执行任务的 Agent 分开设置；执行任务的 Agent 额度不足，不会换掉大脑。
  • 每个任务最多自动尝试 3 次，计划有任务数和时间上限，不会无限重试。

名字的由来

Pyloxa 取自六个英文单词的首字母，正好是它为你做的六件事。

把鼠标移到字母上，看看它代表什么。

  1. P Plan规划

    大脑读过项目，把你的需求拆成一个个任务。

  2. Y Yield交付成果

    只有通过你的验证命令的结果，才会交到你手上。

  3. L Lead主导

    大脑带着各个 Agent 按计划推进，按你的规则派工。

  4. O Orchestrate编排

    Claude Code 和 Codex 分工，一方额度用完时由另一方接手。

  5. X eXecute执行

    每个任务在自己的 git worktree 中执行，不碰你的工作目录。

  6. A Agents你的 Agent

    你已经在用的 AI Agent，用你自己的订阅。
