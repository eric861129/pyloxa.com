从头到尾，看一次实际运行

在一个包含 API、网页和文档的小项目上，配音带你走完一次：Codex 做后端，Claude Code 做网页和文档，Pyloxa 自己运行测试，再请另一家的 Agent 交叉测试。过程中也会介绍工作流程、共享记忆和 Skills。

一个工作流程，五个环节

App 中的“工作流程”页一次展示整个流程：谁来规划、分成哪些阶段、哪类任务交给谁、怎么检查、怎么交付。每个环节都由你设置，大脑只负责提出计划，不能改动这些设置。

检查：Agent 说做完了不算数

你批准的验证命令由 Pyloxa 在任务自己的 worktree 中执行，通过才算完成；没通过，Agent 会自动修复一次。

  • 验证命令需要你批准，例如 npm run test，可以先在临时 worktree 中试运行。大脑只能使用你批准过的命令。
  • 完成的任务可以交给另一个 Agent 测试，例如 Codex 开发、Claude Code 补测试。测试方只能修改测试文件，Pyloxa 会在结果上重新运行你的命令。
  • 大脑可以验收完成的任务，使用它自己的模型和思考强度。结论会标注为 AI 验收；要求你亲自确认的任务，仍然等你决定。

应用前会列出每一项将要改变的设置，“还原上一版”可以回到应用前的状态。模板中属于 Pro 的设置，免费版不会应用。

  • 均衡默认

    前端交给 Claude Code，后端交给 Codex，互为备用；建议后询问。

  • 快速修改

    仅按设置执行，共用一个 worktree，全部交给大脑的 Profile。

  • 严谨审查含 Pro 设置

    大脑验收所有任务，前端和后端的任务交叉测试。

    各类任务在 Claude Code 和 Codex 之间分摊，额度用完时自动交给备用 Agent。

    先写规格，完成后等你批准，再开发和测试；需求用不到测试时可以省略。

存成你自己的流程，每个项目各用一个 Pro

设置好之后点“存成我的流程”，再为每个项目选择要用哪一个，例如 API 项目先写规格、小工具直接改。也可以用一句话描述你想要的做法，让大脑拟好流程。

  • 大脑只负责拟定：阶段、分工和检查方式先列成差异给你看，要“套用到全域”、“存成我的流程”，还是“修改描述”再拟一次，由你选择。
  • 大脑不能自己编造 Agent：不存在或已停用的 Agent 会被移除，做不到的要求会写在说明里。
  • “套用到全域”前会记下目前的设置，可以还原上一版。没有指定流程的项目按全局设置。
  • 每次保存都会留下一个版本，每个流程最多 10 个；可以比较任意两个版本，或还原到其中一个，还原前的内容也会留下一个版本。

不只是多开几个 Agent

能同时开好几个 Agent 的工具已经不少。Pyloxa 处理的是 Agent 之间的事：谁做哪一部分、做完怎么确认、卡住时谁来接手。

下面是同一个需求的三种做法：自己在几个 CLI 之间切换、用终端复用工具把多个 Agent 的终端并排，以及交给 Pyloxa。

不是让 Agent 自己运作的平台

有些平台让 Agent 像一家公司一样自己安排工作、定时醒来、全天运作。Pyloxa 走另一条路：Agent 只做你交代的事，成果经过检查才交给你合并。

  • Windows 原生

    直接在 Windows 10、11 上运行，不需要 WSL、Docker，也不用搭服务器或数据库。

  • Pyloxa 自己跑你的测试

    Agent 说做完了不算数。你批准的验证命令由 Pyloxa 在任务自己的 worktree 中执行，通过才算完成。

  • 不跳过权限确认

    不使用 --dangerously-skip-permissions 这类跳过所有权限确认的模式；改到写入范围以外的文件时，不会自动接受。

  • 不碰你的 CLI 登录

    不读取、复制或发送 CLI 的登录凭证，也不把你的订阅分给别人用。Agent 用的是你自己登录的官方 CLI。

  • 不会自己找事做

    Agent 只做你提出的需求，不会自己生出新的任务；额度用完时停下来，或按你的规则换手。

  • PR 附上验证报告卡

    开 PR 时可以附上验证报告卡：哪些命令真的跑过、谁做了交叉测试、每个成果是怎么被接受的。

先拿示例项目试驾

第一次用，不必拿自己的项目冒险。在设置向导的最后一步点“开始试驾”，Pyloxa 会创建一个小小的购物车示例 repo，请 Agent 加上一个新功能，里面故意藏了一个四舍五入的 bug。

  1. 计划是事先写好的，不经过大脑、不花大脑的额度，同样等你批准才开始。
  2. 一个 Agent 实现新功能，Pyloxa 自己执行测试命令，不看 Agent 怎么说。
  3. 另一家的 Agent 按规格补测试，发现 bug 就退回修复。Pro 自动交叉测试；免费版由你点“交给另一个 Agent 测试”。
  4. 接受结果后，点计划卡下方的“验证报告卡”，看每一步实际做了哪些检查。

需要 git 和 Node.js。只有一个 Agent 时，改用附带的规格测试把关。开始前会先列出谁做、谁测，以及预计的回合数、tokens 和时间。试驾不会碰你的项目，也不会推送或创建 PR。

名字的由来

Pyloxa 取自六个英文单词的首字母，正好是它为你做的六件事。

把鼠标移到字母上，看看它代表什么。

  1. P Plan规划

    大脑读过项目，把你的需求拆成一个个任务。

  2. Y Yield交付成果

    只有通过你的验证命令的结果，才会交到你手上。

  3. L Lead主导

    大脑带着各个 Agent 按计划推进，按你的规则派工。

  4. O Orchestrate编排

    Claude Code 和 Codex 分工，一方额度用完时由另一方接手。

  5. X eXecute执行

    每个任务在自己的 git worktree 中执行，不碰你的工作目录。

  6. A Agents你的 Agent

    你已经在用的 AI Agent，用你自己的订阅。
