# Pyloxa website

Static site for Pyloxa, served by GitHub Pages as committed (no build on the server). The home page exists in nine languages: `index.html` (English) and `zh-TW/`, `zh-CN/`, `ja/`, `ko/`, `es/`, `pt-BR/`, `de/`, `fr/`. The changelog, privacy policy and help pages exist in English and 繁體中文 only; the other languages link to the English ones.

## Home pages are generated

Don't edit the `index.html` files by hand. They're generated from `src/home.html` (the template) and `src/i18n/<lang>.json` (one file per language, same keys as `en.json`; each value is an HTML fragment). `src/languages.json` lists the languages (folder, `lang`, hreflang, Open Graph locale and image, which screenshots to use, and whether the app UI is in that language). `src/site.json` holds the app version and the installer's SHA-256 and size. `src/download.html` is the template for the download page (`/download/` and `/<lang>/download/`, same language files, keys `dl.*`); every download button on the site goes there with `#start`, and the page then downloads the installer directly.

- `node scripts/build-pages.mjs` writes every home page and `sitemap.xml`, including the hreflang links, the language menu, the SoftwareApplication JSON-LD and the FAQ structured data (`scripts/build-schema.mjs`). `--check` only reports what would change.
- `node scripts/check-i18n.mjs [lang…]` checks that a language file has every key, keeps the HTML tags and `{{@…}}` values, and that the page JSON still parses. Run it after editing any language file.
- `node scripts/check-links.mjs` checks that every internal link and `#anchor` on every page points to a file and an `id` that exist. Run it after editing any page. `build-pages.mjs` also stops if a sub-page listed under `pages` in `src/languages.json` doesn't exist.
- To change text: edit `src/i18n/en.json` and the same key in every other language file (or the template for markup), then build. A key missing from a language falls back to English with a warning.
- To add a language: add it to `src/languages.json`, write `src/i18n/<code>.json` from `en.json`, run the check and the build (IndexNow picks the new URL up from `sitemap.xml`).
- `scripts/extract-i18n.py` was the one-time conversion from the hand-written pages; it's kept for reference only.

## Guides are generated

`/guides/` and `/guides/<slug>/` (and the same pages under `zh-TW/`) are generated by `node scripts/build-guides.mjs` (`--check` only reports changes). Don't edit their `index.html` files.

- `src/guides/guides.json` lists the guides in order and the languages that have them. `build-pages.mjs` reads it for the sitemap and the home page footer link.
- `src/guides/<slug>/<lang>.html` is the article body: short answer, sections, a "Where Pyloxa fits" section, FAQ and sources. Its first line is `<!--meta {"title", "description", "h1", "lede", "nav", "blurb", "updated"}-->`. The script adds the head (TechArticle, breadcrumb and FAQ structured data), the header with the updated date, the download box, related guides and the footer.
- Every claim about Claude Code, Codex or Gemini CLI must cite an official source in the Sources list, checked on the `updated` date. Re-check and bump `updated` when a vendor changes something.

## Feature pages are generated

`/workflow/`, `/memory/`, `/quota/` and `/pro/` (and the same pages under `zh-TW/`) are generated by `node scripts/build-features.mjs` (`--check` only reports changes). Don't edit their `index.html` files by hand.

- `src/features/pages.json` lists the pages, their nav labels and one-line descriptions, and the languages that have them (English and 繁體中文). `build-pages.mjs` reads the same file to add the pages to `sitemap.xml` and to link the home pages to them (other languages link to the English page).
- `src/features/<page>/<lang>.html` is the content inside `<main>`. Its first line is `<!--meta {"title": …, "description": …}-->`. The script adds the head, hreflang links, nav, closing call to action, related pages, footer, Google Analytics (copied from `src/home.html`) and JSON-LD (WebPage, BreadcrumbList, and FAQPage from `<details class="fx-q">` items).
- Styles are in `assets/features.css`, on top of `site.css`. Mockups reuse the app components (`[data-ui]`).
- Feature pages only describe what the released version does. Rebuild them, and the home pages, after editing.
- IndexNow takes its URL list from the deployed `sitemap.xml`, so new pages don't need to be added to `.github/workflows/indexnow.yml`.

## Notes

- Download links point to the latest release in [Pyloxa-Releases](https://github.com/eric861129/Pyloxa-Releases/releases/latest).
- Each release: update `version` and `installer` (`sha256`, `bytes`, from the GitHub release asset) in `src/site.json` and run `node scripts/build-pages.mjs` (it updates the version on every home page, the JSON-LD and the sitemap dates). Then regenerate the changelog pages (`changelog/` and `zh-TW/changelog/`) from the release notes: `node scripts/build-changelog.mjs ../Pyloxa-Releases`. Commit the release notes in Pyloxa-Releases first; the release date is the date of that commit.
- `assets/og-en.png` and `assets/og-zh.png` are the 1200×630 link-preview images (rendered from the wordmark and `assets/shots/<lang>/plan-card.png`). Icons (`favicon.ico`, `assets/favicon.svg`, `assets/apple-touch-icon.png`, `assets/site.webmanifest`) come from the app repo's `brand/web/`.
- Fonts are self-hosted: Archivo (Latin only, 400 and 600) in `assets/fonts/` from `@fontsource/archivo` 5.3.0 under the OFL (`assets/fonts/Archivo-OFL.txt`). Chinese, Japanese and Korean text uses each system's own fonts (set per language in `site.css`). Don't add Google Fonts or another font CDN: it blocks the first paint on phones, and the privacy policy says no font service receives visitors' IP addresses.
- Page views are counted with Cloudflare Web Analytics (cookieless; manual JS snippet before `</body>` on each page, because the site is DNS-only and not proxied). The footer says so. Search Console uses the domain property `sc-domain:pyloxa.com` with `sitemap.xml` submitted. Google Analytics 4 property "Pyloxa" (account Chiyu-GitHub-Project, measurement ID `G-PWKKJHQV92`) is in the `<head>` of every home page and `404.html`: advertising features off. It is not loaded at all when the device time zone is in Europe (`Europe/*`, `Atlantic/*`, `Arctic/*`, Cyprus and the EU's overseas regions) or is UTC, `Etc/*` or unreadable, so there is no consent banner; the region-based consent default (analytics cookies denied in the EEA, UK and Switzerland) stays as a second layer. It sends `download_click` (release links) and `generate_lead` (early-bird form) events. Bing Webmaster Tools is verified by the `msvalidate.01` meta tag in `index.html`; keep it. After each Pages build, `.github/workflows/indexnow.yml` pings IndexNow (key file `c11e770d29e531bffe32789c008327a4.txt` at the root; keep it). Add new pages to its `urlList`.
- Structured data: the `SoftwareApplication` block and the `site-graph` block (Organization, WebSite and FAQPage built from the FAQ on that page) in each home page's `<head>` are generated by `scripts/build-pages.mjs`.
- `llms.txt` is a plain-text summary of Pyloxa for AI assistants (what it is, requirements, free vs Pro, privacy, links). Keep it in step with the site: update it when pricing, Pro features, supported agents or data collection change. `robots.txt` explicitly allows the AI search and assistant crawlers (GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended and others).
- `privacy/` and `zh-TW/privacy/` are the privacy policy (hand-written; linked from the footer). Update both, and the date at the top, whenever the site or the app starts collecting or sending something new, and before Pro sign-in and payments (D-78) or the opt-in usage statistics (D-79) ship.
- `help/` and `zh-TW/help/` are the help pages (hand-written; linked from the footer as `footer.27`). Write them from what the app actually does, mark Pro features with `<span class="pro">Pro</span>`, and update both when a release changes a feature, a menu path or a free/Pro limit. The other seven languages link to the English page until they are translated.
- `legal/` holds copies of the EULA and third-party notices shipped with the installer; update them with each release.
- Screenshots in `assets/shots/` are taken from the app with demo data.
- Screen recordings in `assets/video/<lang>/` (VP9 WebM, poster = last frame) are recorded from the app with demo data; waits for agents are cut out. They play when scrolled into view and pause on click.
- The Pro early-bird form posts to the endpoint in `<meta name="pyloxa:waitlist">` on each page (Buttondown's `https://buttondown.com/api/emails/embed-subscribe/<username>`). While it is empty, the pricing table shows "sign-up opens soon" instead of the form.
