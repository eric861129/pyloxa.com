# Pyloxa website

Static site for Pyloxa, served by GitHub Pages as committed (no build on the server). The home page exists in nine languages: `index.html` (English) and `zh-TW/`, `zh-CN/`, `ja/`, `ko/`, `es/`, `pt-BR/`, `de/`, `fr/`. The changelog and privacy policy exist in English and 繁體中文 only; the other languages link to the English ones.

## Home pages are generated

Don't edit the `index.html` files by hand. They're generated from `src/home.html` (the template) and `src/i18n/<lang>.json` (one file per language, same keys as `en.json`; each value is an HTML fragment). `src/languages.json` lists the languages (folder, `lang`, hreflang, Open Graph locale and image, which screenshots to use, and whether the app UI is in that language). `src/site.json` holds the app version.

- `node scripts/build-pages.mjs` writes every home page and `sitemap.xml`, including the hreflang links, the language menu, the SoftwareApplication JSON-LD and the FAQ structured data (`scripts/build-schema.mjs`). `--check` only reports what would change.
- `node scripts/check-i18n.mjs [lang…]` checks that a language file has every key, keeps the HTML tags and `{{@…}}` values, and that the page JSON still parses. Run it after editing any language file.
- To change text: edit `src/i18n/en.json` and the same key in every other language file (or the template for markup), then build. A key missing from a language falls back to English with a warning.
- To add a language: add it to `src/languages.json`, write `src/i18n/<code>.json` from `en.json`, run the check and the build, and add the URL to `.github/workflows/indexnow.yml`.
- `scripts/extract-i18n.py` was the one-time conversion from the hand-written pages; it's kept for reference only.

## Notes

- Download links point to the latest release in [Pyloxa-Releases](https://github.com/eric861129/Pyloxa-Releases/releases/latest).
- Each release: update `version` in `src/site.json` and run `node scripts/build-pages.mjs` (it updates the version on every home page, the JSON-LD and the sitemap dates). Then regenerate the changelog pages (`changelog/` and `zh-TW/changelog/`) from the release notes: `node scripts/build-changelog.mjs ../Pyloxa-Releases`. Commit the release notes in Pyloxa-Releases first; the release date is the date of that commit.
- `assets/og-en.png` and `assets/og-zh.png` are the 1200×630 link-preview images (rendered from the wordmark and `assets/shots/<lang>/plan-card.png`). Icons (`favicon.ico`, `assets/favicon.svg`, `assets/apple-touch-icon.png`, `assets/site.webmanifest`) come from the app repo's `brand/web/`.
- Fonts are self-hosted: Archivo (Latin only, 400 and 600) in `assets/fonts/` from `@fontsource/archivo` 5.3.0 under the OFL (`assets/fonts/Archivo-OFL.txt`). Chinese, Japanese and Korean text uses each system's own fonts (set per language in `site.css`). Don't add Google Fonts or another font CDN: it blocks the first paint on phones, and the privacy policy says no font service receives visitors' IP addresses.
- Page views are counted with Cloudflare Web Analytics (cookieless; manual JS snippet before `</body>` on each page, because the site is DNS-only and not proxied). The footer says so. Search Console uses the domain property `sc-domain:pyloxa.com` with `sitemap.xml` submitted. Google Analytics 4 property "Pyloxa" (account Chiyu-GitHub-Project, measurement ID `G-PWKKJHQV92`) is in the `<head>` of every home page and `404.html`: advertising features off. It is not loaded at all when the device time zone is in Europe (`Europe/*`, `Atlantic/*`, `Arctic/*`, Cyprus and the EU's overseas regions) or is UTC, `Etc/*` or unreadable, so there is no consent banner; the region-based consent default (analytics cookies denied in the EEA, UK and Switzerland) stays as a second layer. It sends `download_click` (release links) and `generate_lead` (early-bird form) events. Bing Webmaster Tools is verified by the `msvalidate.01` meta tag in `index.html`; keep it. After each Pages build, `.github/workflows/indexnow.yml` pings IndexNow (key file `c11e770d29e531bffe32789c008327a4.txt` at the root; keep it). Add new pages to its `urlList`.
- Structured data: the `SoftwareApplication` block and the `site-graph` block (Organization, WebSite and FAQPage built from the FAQ on that page) in each home page's `<head>` are generated by `scripts/build-pages.mjs`.
- `llms.txt` is a plain-text summary of Pyloxa for AI assistants (what it is, requirements, free vs Pro, privacy, links). Keep it in step with the site: update it when pricing, Pro features, supported agents or data collection change. `robots.txt` explicitly allows the AI search and assistant crawlers (GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended and others).
- `privacy/` and `zh-TW/privacy/` are the privacy policy (hand-written; linked from the footer). Update both, and the date at the top, whenever the site or the app starts collecting or sending something new, and before Pro sign-in and payments (D-78) or the opt-in usage statistics (D-79) ship.
- `legal/` holds copies of the EULA and third-party notices shipped with the installer; update them with each release.
- Screenshots in `assets/shots/` are taken from the app with demo data.
- Screen recordings in `assets/video/<lang>/` (VP9 WebM, poster = last frame) are recorded from the app with demo data; waits for agents are cut out. They play when scrolled into view and pause on click.
- The Pro early-bird form posts to the endpoint in `<meta name="pyloxa:waitlist">` on each page (Buttondown's `https://buttondown.com/api/emails/embed-subscribe/<username>`). While it is empty, the pricing table shows "sign-up opens soon" instead of the form.
