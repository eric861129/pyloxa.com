에이전트를 더 띄우는 것 이상

여러 에이전트를 나란히 실행하게 해 주는 도구는 많습니다. Pyloxa는 그 사이에서 일어나는 일을 맡습니다. 누가 어느 부분을 하는지, 끝났는지 어떻게 아는지, 하나가 막히면 누가 이어받는지입니다.

같은 요청을 세 가지 방식으로 비교합니다. CLI를 직접 오가며 작업하는 방식, 터미널 멀티플렉서에 여러 에이전트 터미널을 나란히 띄우는 방식, 그리고 Pyloxa에 맡기는 방식입니다.

CLI 직접 전환 터미널 멀티플렉서 Pyloxa 사용
작업 나누기 어느 부분에 어떤 도구가 맞는지 직접 판단하고 요청을 옮겨 붙여 넣습니다. 각 터미널의 에이전트가 할 일을 직접 정합니다. 일부 도구는 에이전트가 보조 에이전트를 띄우게 해 줍니다. 브레인이 요청을 단계와 작업으로 나누고 내 규칙에 따라 각각 배정하며, 일치한 규칙을 함께 표시합니다.
인계 한 에이전트가 끝나면 API 형태와 파일 경로를 다음 에이전트에게 직접 붙여 넣습니다. 에이전트끼리 메시지를 주고받을 수 있지만, 무엇을 넘길지는 에이전트에게 달려 있습니다. 다음 단계는 인계 패키지를 받습니다. 결과, 통과한 검증, 주의할 점이 들어 있습니다.
완료의 기준 에이전트가 끝났다고 하면 직접 테스트를 돌려 확인합니다. 어느 에이전트가 작업 중인지, 끝났는지, 나를 기다리는지는 보입니다. 결과가 맞는지는 여전히 직접 확인해야 합니다. 작업 자체의 worktree에서 검증 명령을 통과해야 완료입니다. 실패하면 에이전트가 자동으로 한 번 수정합니다. 다른 에이전트에게 테스트를 작성하게 하거나 브레인에게 검토를 맡길 수도 있으며, 브레인의 판정은 AI 검토로 표시됩니다.
한도 소진 도구를 바꾸고 어디까지 했는지 다시 설명합니다. 해당 터미널은 멈춰서 기다립니다. 누가 이어받을지는 직접 정해야 합니다. Pyloxa가 내 규칙에 따라 대체 에이전트를 제안하고, 확인하면 첫 에이전트가 바꾼 파일에서 이어서 작업합니다.
내 저장소 에이전트가 작업 디렉터리를 직접 수정합니다. 터미널을 여는 방식에 따라 다르며, 보통 작업 디렉터리에서 실행됩니다. 모든 작업은 자체 git worktree에서 진행되며, 변경 사항이 허용된 쓰기 범위 안인지 확인합니다. 병합과 푸시는 직접 결정합니다.
이럴 때 적합 한 번에 한 가지 일만 할 때. 여러 터미널을 한꺼번에 지켜보거나, 앱을 종료한 뒤에도 에이전트를 계속 실행하거나, 원격 머신에서 작업할 때. 요청 하나를 여러 에이전트에게 나눠 맡기고, 병합하기 전에 결과를 검증하고 싶을 때.

작동 방식

먼저 원하는 것을 말합니다.

회원이 닉네임과 아바타를 수정할 수 있는 프로필 페이지를 만들어 줘. 백엔드에는 API와 문서가 필요해.

그다음 계획을 승인합니다.

한 번에 한 에이전트가 작업하며, 각자 자체 git worktree를 씁니다.

마지막으로 통과한 결과를 병합합니다.

전체 계획의 결과 (파일 5개)
  • Adocs/api/profile.yaml
  • Aserver/src/routes/profile.ts
  • Aweb/src/pages/Profile.tsx
  • Atest/profile.test.ts
  • Atest/contract.test.ts
main에 병합했습니다. 직접 푸시하기 전에는 아무것도 푸시되지 않습니다.

작업을 원하는 방식으로 나누기

어떤 모델을 쓸지, 어떤 일을 누구에게 맡길지, Pyloxa가 언제 멈추고 물어볼지는 모두 내 설정입니다. 브레인은 계획을 제안할 뿐 이 설정을 바꿀 수 없습니다.

모든 에이전트는 직접 설정하는 프로필입니다

프로필에서는 CLI, 모델, 추론 수준, 그리고 모든 작업에 덧붙일 역할 프롬프트를 고릅니다. CLI 하나에 "Claude 프론트엔드", "Claude 문서"처럼 프로필을 여러 개 둘 수 있습니다.

  • 모델 목록은 설치한 CLI에서 그대로 가져옵니다. 추론 수준은 임의의 공통 척도로 바꾸지 않고 각 CLI의 원래 값(Claude Code의 --effort, Codex의 model_reasoning_effort)을 그대로 보여 줍니다.
  • 어떤 프로필이든 프로젝트를 읽고 계획을 쓰는 브레인이 될 수 있으며, 브레인은 실제 작업하는 에이전트와 다른 모델을 쓸 수 있습니다.
  • 프로필에는 설정만 저장되며, 자격 증명은 절대 저장되지 않습니다.

누가 무엇을 할지는 내 규칙이 정합니다

규칙은 단계 유형과 작업 유형으로 일치 여부를 판단합니다. 예를 들어 "구현 단계의 백엔드 작업은 Codex 백엔드에게" 같은 식입니다. 규칙마다 기본 프로필과 대체 순서가 있으며, 모든 프로젝트에 적용하거나 현재 프로젝트에만 적용할 수 있습니다.

  • 규칙은 위에서 아래로 확인하며, 처음으로 완전히 일치한 규칙이 적용됩니다. 한 규칙이 다른 규칙을 가리면 Pyloxa가 경고합니다.
  • 규칙 시뮬레이션은 에이전트를 호출하지 않고 한도도 쓰지 않습니다. 작업 종류를 고르면 누가 맡는지와 그 이유를 보여 줍니다.
  • 일치하는 규칙이 없으면, 설정에 따라 계획 미리보기에서 묻거나 멈춥니다. 에이전트를 무작위로 고르지 않습니다.

모든 단계를 내 명령으로 검증합니다

브레인은 요청에 맞춰 사양, 계약, 구현, 테스트 같은 단계를 구성합니다. 승인하기 전에 작업을 다른 에이전트에게 재배정하거나, 지시를 고치거나, 브레인에게 수정을 요청할 수 있습니다.

  • 검증 명령(예: npm run test)은 승인을 받아야 하며, 먼저 임시 worktree에서 시험 실행해 볼 수 있습니다. 브레인은 승인된 명령만 사용할 수 있습니다.
  • 완료된 작업은 각자의 worktree에서 검증하고, 각 단계가 끝나면 통합된 결과에서 게이트를 한 번 더 실행합니다.
  • 게이트는 통과하면 자동으로 다음으로 넘어가게 하거나, 내 승인을 기다리게 할 수 있습니다.
  • 완료된 작업을 다른 에이전트에게 넘겨 테스트하게 할 수 있습니다. 예를 들어 Codex가 구현하고 Claude Code가 테스트를 작성합니다. 테스트 담당은 테스트 파일만 바꿀 수 있으며, Pyloxa가 그 결과에서 내 명령을 다시 실행합니다.
  • 브레인은 자체 모델과 사고 수준으로 완료된 작업을 검토할 수 있습니다. 판정은 AI 검토로 표시되며, 내 검토를 요구하는 작업은 여전히 나를 기다립니다.

얼마나 맡길지는 직접 정합니다

라우팅 모드는 Pyloxa가 언제 먼저 물어볼지를 정합니다. 어느 모드에서든 푸시와 배포는 저절로 일어나지 않습니다.

  • 브레인과 작업 에이전트는 따로 설정합니다. 작업 에이전트의 한도가 소진되어도 브레인이 교체되지는 않습니다.
  • 작업마다 자동 시도는 최대 3번이고 계획에는 작업 수와 시간 제한이 있어, 끝없이 재시도하지 않습니다.
제안 후 확인기본값무료
브레인이 계획과 작업별 담당을 제안하며, 계획을 승인하기 전에는 아무것도 시작하지 않습니다.
설정대로만 실행무료
모든 작업이 규칙과 일치하면 바로 시작하고, 일치하는 규칙이 없거나 프로필을 쓸 수 없으면 멈춥니다.

허용한 프로필, 모델, 횟수 안에서 선택과 재시도를 하고, 한도에 이르면 일시 정지합니다.
개발 중

모든 에이전트를 위한 하나의 스킬 세트

Claude Code는 ~/.claude/skills를, Codex는 ~/.agents/skills를 읽습니다. 같은 스킬을 양쪽에 복사해 두면 한쪽을 바꿀 때 다른 쪽은 낡은 상태가 됩니다. Pyloxa는 이를 한곳에서 관리합니다.

  1. 목록 확인무료각 CLI에 어떤 스킬이 있는지, 이름은 같지만 내용이 다른 스킬은 무엇인지 보여 줍니다.
  2. 동기화Pro공용 라이브러리 ~/.agents/skills를 모든 CLI에 동기화합니다. CLI 쪽에서 바꾼 파일은 묻지 않고 덮어쓰지 않습니다.
  3. 지정Pro프로젝트마다 쓸 스킬을 고릅니다. Claude Code와 Codex는 프로필별로도 지정할 수 있습니다.
  4. 라우팅 팩Pro규칙, 스킬, 단계, 검증 명령을 묶어 공유합니다. 가져올 때는 각 항목을 먼저 보여 주며, 기존 규칙을 대체하지 않습니다.

한도가 바닥나면

Codex가 작업 도중 사용 한도에 걸리면, Pyloxa는 Codex에 작업 보내기를 멈추고 한도가 언제 초기화되는지 보여 주며 내 규칙에 따른 대체 에이전트를 제안합니다. 확인하면 Claude Code가 Codex가 이미 바꾼 파일에서 이어서 작업합니다.

작업당 자동 시도 3번 대체는 최대 2번 허용하지 않은 API 요금 0건

모든 작업에 내 테스트를 돌려 줘.

npm run test가 작업마다 자체 worktree에서 실행됩니다. 통과하면 작업이 자동으로 수락되고, 실패하면 에이전트가 자동으로 한 번 수정합니다.

다음 단계로 가기 전에 물어봐 줘.

단계는 통합된 버전에서 명령을 통과한 뒤 내 클릭 한 번을 기다립니다. 이 옵션을 끄면 검증을 통과한 단계는 저절로 다음으로 넘어갑니다.

내 자격 증명은 절대 건드리지 마.

Pyloxa는 내가 로그인한 CLI를 실행할 뿐입니다. CLI의 토큰을 읽거나 복사하거나 보내지 않으며, 작업 디렉터리를 stash하거나 reset하지 않습니다.

내 언어로 답해 줘.

인터페이스와 에이전트 답변의 언어를 English, 繁體中文, 简体中文 중에서 각각 따로 고를 수 있습니다.
